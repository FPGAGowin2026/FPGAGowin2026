## 一、结论

这套资料不是一个单一应用工程，而是一套面向 ACG720 / GW5AT-138K 的 70 章递进式 FPGA 教程：从 LED、计数器、UART 和状态机开始，逐步覆盖 Gowin RAM/FIFO/PLL、ADC/DAC、VGA/TFT/HDMI、I2C/RTC/ES8388、DDR3、图像滤波、OV5640、RGMII/UDP，以及 Cypress FX2 USB2.0 Slave FIFO 数据传输。

已完成对全部 PDF、压缩包、工程和 HDL 的遍历、提取、模块审计与批量构建：

- 70 份 PDF、1,340 页全部提取文本；68 个外层源码压缩包和第 33 章 2 个嵌套压缩包全部解包。
- 找到 75 个 Gowin `.gprj`，所有 802 条已启用文件引用均存在。
- 发现 1,580 个 HDL 文件、1,054 个模块声明、395 个唯一模块名；其中 328 个为设计/生成 IP，67 个为 testbench。原 `.gprj` 实际启用了 220 个唯一模块名。
- 75/75 原工程在其声明器件上重新综合通过。
- 原样 P&R 为 68/75；对 6 个明确的 PLL/配置脚兼容问题建立独立规范化工程后，这 6 个全部生成位流。按各工程声明器件计，共 74/75 可生成位流，唯一剩余的是第 37 章无板级 CST 的 DDR3 核心示例。
- 位流成功不代表时序闭合：68 个原样 P&R 成功工程中 40 个 setup/hold 违例端点为 0，28 个仍有违例；6 个兼容工程中 2 个干净、4 个仍有违例。合计 74 个可出位流工程中，42 个时序干净、32 个仍需收敛。
- Tang Primer 25K 上完成了严格自检仿真、综合、P&R、SRAM 下载和 UART 实收；同一 BIST 已迁到最终 GW5AT-138B 器件并完成干净时序的位流，但尚无 138K 实板可下载。

## 四、综合与仿真结果

### 4.1 Gowin 综合

- 原始 `.gprj`：75/75 PASS。
- 对容易自动选错顶层的工程另做语义顶层验证：第 15 章 `Gowin_SP`、第 16 章 `fifo_top`、第 51 章两个方向 `gmii_to_rgmii` / `rgmii_to_gmii`、第 66 章 `usb_stream_out`，共 5/5 PASS。
- 第 44 章只有散装 HDL、没有 `.gprj`；补建 `DVP_Capture` 和 `camera_init` 两个规范化 GW5AT-138B 综合工程，2/2 PASS，未虚构板级引脚约束。

### 4.2 Icarus 仿真

- 自动发现 28 个原工程 testbench：21 个编译通过并完成 1 ms 有界运行，7 个编译失败。
- 第 12 章失败是 testbench 实例化名 `key_led` 与设计名 `key_led_top` 不一致；兼容别名后原 testbench PASS。
- 第 16、37、55、60、66 章的 6 个失败目标依赖 Gowin `` `pragma protect`` 加密/保护 IP 包装器，Icarus 不能解析；这不等于 Gowin 综合失败。
- 规范化仿真：第 12 章兼容 testbench、第 44 章原 DVP testbench，2/2 PASS。
- 这些教程 testbench 很多没有 `$finish` 或断言；1 ms 有界运行证明能编译和推进，不应冒充完整功能证明。25K BIST 的 testbench 是另外编写的严格自检式门禁。

证据：`reports/iverilog_results.csv`、`reports/normalized_sim_results.csv`、`reports/semantic_top_results.csv`。

### 时序结论

`reports/pnr_timing_audit.csv` 对每个当前 P&R 报告单独读取 setup/hold 违例端点：

- 原样成功的 68 工程：40 个 CLEAN，28 个 VIOLATED。
- 6 个兼容工程：2 个 CLEAN，4 个 VIOLATED。
- 因此“生成位流”可以作为实现可行性证据，但第 56、61、62、63 章以及另外 28 个原样工程仍不能声称完成时序闭合。实际比赛工程应只保留所需时钟域，补齐 SDC、CDC 和 I/O 时序，再重新收敛。

## 六、25K 测试板上的实际复现

## 八、没有完成实物验证的内容

以下外设需要 ACG720 板、对应扩展模块、线缆或网络/USB 主机，本次没有接到 25K，也没有 138K 实板可测：

- 板载 DDR3 及其板级校准；
- OV5640 单/双摄像头和 DVP 电气接口；
- TFT、VGA/GM7123、HDMI/DVI 显示链路；
- RGMII 千兆 PHY、MDIO、ARP/UDP 真实网络收发；
- ES8388 音频、AD9767/TLV5618 DAC、ADC128S102、AD7606/ACM7606、ACM1030；
- Cypress FX2 固件、驱动和 Slave FIFO 实物传输。

第 36 章还存在器件不一致：原工程是 `GW5AST-LV138FPG676AES`，不是比赛板 `GW5AT-LV138PG484AC1/I0`。DDR IP 与 DQ/DQS 位置强相关，必须在最终器件和官方板级引脚上重新生成，不能只替换器件字符串。

## 九、D435i 的边界

Intel RealSense D435i 不在这套教程中。本教程第 64–70 章的 Cypress FX2 是 USB2.0 外设侧/Slave FIFO 数据通道，并不会把 FPGA 变成 USB 主机；因此这些章节不能证明 D435i 可以直接接 FPGA。

D435i 若加入比赛系统，工程上应把它视为 USB3 主机设备：由带 USB 主机控制器和 RealSense 软件栈的 PC/嵌入式 SoC 取流，再通过千兆以太网、PCIe、并行 FIFO 等受控接口把深度/图像数据送给 FPGA；或者选用具备完整 USB3 Host IP、PHY 和协议实现的专用 FPGA 平台。本次没有 D435i、USB3 Host IP 或相应桥接硬件，因此未做实测，也不声称直连兼容。

## 十、下一步落到比赛选题 3

1. 拿到 ACG720 后，先下载 `portable_138k_bist`，用 UART 重复 25K 的整链路自检，确认时钟、复位、JTAG 和串口。
2. 根据选题 3 真正需要的传感器，只抽取对应章节模块，不要把 70 章全部合成进一个系统。
3. 若使用 DDR3，按官方 ACG720 原理图/CST 在最终器件重新生成内存 IP；先通过独立 DDR 读写压力测试，再接图像/网络。
4. 若使用 RGMII/UDP，优先从时序干净的第 48/54 章兼容工程建立链路，再逐步加入接收、DDR3 和传感器数据；每一步都检查 `pnr_timing_audit` 类似的端点统计。
5. D435i 保留在主机/SoC 侧，FPGA 负责低时延传感、预处理、时序控制和确定性接口，除非后续明确选定并验证 USB3 Host 方案。
