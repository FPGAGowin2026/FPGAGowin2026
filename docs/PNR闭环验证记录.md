1. 综合与 PNR 分开计时；PNR 从 `BUILD_START pnr` 标记开始。每轮实际 PNR 上限 1800 秒。
2. 达到上限仍未完成时停止本轮工具进程树，保留日志与中间文件，结果不得缓存为通过。
3. 超时或门禁失败后，依据报告定位组合路径、扇出、资源和拥塞，实施有依据的精简、流水或资源复用；完成相关回归与重新综合后再运行新 PNR。
4. 保留双版本雷达建图/回环、UDP 视频、控制、定位、打滑、独立避障与现有协议；不通过删除功能、降低目标频率或放宽门限获得通过。
5. 每轮独立输出目录，保存源码/工具/选项指纹、各阶段耗时、终止原因和产物哈希。只复用输入身份匹配的综合结果。
6. 默认顺序执行两版 PNR，避免相互争用资源影响 30 分钟判断。原有网页工作、验收文件和 29 个备份哈希保持；本轮不推送或烧录。

## 通过标准与边界

两版分别在 PNR 不超过 1800 秒的条件下生成匹配的位流，并通过当前 `radar_slam` 时序、资源和告警门禁。蓝牙门禁必检 5 个命名时钟，UDP 门禁必检含 RX 在内的 8 个时钟；这不是 UDP SDC 所有时钟的总数，独立审查还覆盖 RX 引脚/HCLK、相机 XCLK 等实际报告项。独立核对 setup/hold/recovery/removal、Fmax、负端点和位流 SHA-256。若重构改变输入，旧结果不继承。

时序检查器不单独统计复位 `set_false_path` 通配符的匹配对象。若本轮工具没有输出逐对象 exception 应用报告，审查只将“SDC 无解析错误、综合网表路径相符”记为现有证据，不将其写成已独立证明每个例外均命中。

PNR 与内部 STA 不等于厂商 DDR 颗粒仿真、实板校准、外部 IO 或机械运动验收。本轮没有授权的硬件下载或运动操作。
