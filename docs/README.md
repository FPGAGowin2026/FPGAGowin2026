## 系统总体方案

BX72 将四轮编码器、IMU 和雷达用于本地融合，同时由独立 N10 规划器处理低速避障；规划器不依赖 EKF 或 Jetson。当前提供两个互斥的通信工程：

| 版本 | 控制与显示 | 活动硬件 |
| --- | --- | --- |
| 蓝牙 | 网页经蓝牙 UART 控制，接收 v4 融合/规划遥测 | 电机、编码器、IMU、N10、定位/打滑/避障，DDR3 雷达 SLAM 建图；无相机和以太网 |
| UDP | Jetson 网关转发 PC 三轴速度，接收传感器与视频 | 共同机器人核心、以太网、OV5640；本轮新增 DDR3 视频与雷达 SLAM 地图共享，无蓝牙 |

BX72 当前没有 GoRV32/APB、TFT 或 USB 电机调试接口。ACG720 是独立的 TFT、GoRV32、BXT1 工程，当前资源/时序未通过整板验收，不能复用 BX72 位流。

两版地图均为 1024×1024 格、64 mm/格、6 bit/格，含关键帧回环修正和地图重建。源分支先提供蓝牙建图，本轮按追加要求扩展 UDP。现有网页显示的雷达/轨迹不是 DDR 地图；两版均没有地图下载、网页栅格显示或 ROS 地图发布协议，见 [建图设计](../FPGA_ws/boards/BX72_138K_robot/docs/radar_slam_mapping.md)。

FPGA 负责采集、速度环、融合与本地租约停车；Jetson 承担接入、显示、记录和后续导航。自动避障默认关闭，只实现局部通道选择，没有目的地/路径点输入。涉及软核独立任务的赛题要求仍需另行部署验证。

车体系 x 前、y 左、z 上；局部 odom 与全局 map 修正分开。ROS Header 为主机接收时间，FPGA timestamp_us 为采集提交时间，二者尚未完成时间映射。避免重复融合来自同一轮速/IMU 的原始量和融合结果。

## 公共 RTL 与研究模块

| FPGA_ws 路径 | 用途 |
| --- | --- |
| `boards/` | BX72、ACG720、25K 的独立工程、约束和手册 |
| `rtl/common/cdc`、`rtl/ethernet` | BX72 使用的异步帧 FIFO 与 UDP RX |
| `rtl/motor`、`sim/` | 电机参数对照、两板融合及离线回归 |
| `Scripts/` | 统一构建、仿真、时序和协议检查 |

构建入口见 [FPGA_ws README](../FPGA_ws/README.md)，硬件细节见 [BX72](../FPGA_ws/boards/BX72_138K_robot/README.md)、[ACG720](../FPGA_ws/boards/ACG720_60K_robot/README.md)。旧候选和优化试验过程可从 Git 历史查询。
