## 系统总体方案

更新：2026-10-05。本文维护系统职责和数据流；进度见[项目状态](handoff.md#项目状态与交接)，排期见[开发计划](handoff.md#后续开发计划)。赛题独立部署边界见下文。

### 平台与职责

当前主线为 BX72 V2.1 / GW5AT-138C、四轮麦轮、AT8236、四轮编码器、IMU660RC（LSM6DSV16XTR，SPI）、N10、OV5640 和 Jetson Orin Nano。ACG720-60K 保留独立 TFT 集成与 GoRV32 固件，两板工程不互换。

| 执行部分 | 职责 | 接口边界 |
| --- | --- | --- |
| FPGA RTL | 采集/时间戳、四轮运动学与速度环、局部 EKF、近障约束和输出仲裁 | 接收车体速度请求，保持轮速反馈和本地停车独立运行 |
| Jetson | ROS 接收、显示/记录、联调；协同模式的全局定位、规划与任务扩展 | 发送 vx/vy/wz，不直接写 PWM |
| 软核 | 初始化、参数和诊断；独立基础任务中的路径点/局部绕障 | 输出有时效的速度请求，不绕过硬件仲裁 |

UDP 三轴速度、WASD 网关、会话/序号与停车已实现；最新融合候选已完成离线/构建验证，当前候选实板验收待执行。轮位/极性已确认，测速尺度、负载速度响应、定位、近障停车和导航仍分别验收。

### 数据流

```text
OV5640 → DDR3 双缓冲 → RTP/UDP → Jetson 视频
四轮编码器 → 测速 ─┬→ 对应轮速度环反馈
                   └→ 麦轮 FK ─┐
IMU660RC → SPI/时间戳 ──────────┼→ 局部 EKF → 位姿/速度/质量
N10 → 解析/时间戳 ─┬→ 扫描匹配 ┘
                  ├→ 近距约束 ─────────────────┐
                  └→ 遥测/导航输入             │
Jetson 或软核速度请求 → 有效性/仲裁 → 麦轮 IK → 四轮速度环 → AT8236
                                               ↑
                                    超时/近障停车约束
```

图中的采集、速度控制、UDP 及局部 EKF 已有实现；软核任务级速度来源、近障反射和导航仍为目标链路。上传或显示拥塞不能阻塞轮速反馈和本地停车。BX72 已移除 TFT；姿态与状态显示在 Jetson 端推进，ACG720 另保留 TFT。

### 运动与定位

轮速环使用对应编码器反馈；融合车体速度不替代各轮反馈。CH 映射、符号、几何和测速参数以本板辨认/标定记录为准。运动学矩阵、增量速度环和 PWM 模式统一见[运动控制文档](控制与定位.md#运动控制与日志分析)，本板接线和调试见[BX72 接口](../FPGA_ws/boards/BX72_138K_robot/docs/hardware_interfaces.md)。

当前两板已有七状态定点 EKF：x/y/yaw/vx/vy/wz/陀螺零偏。模型、定点格式、时间处理、局部扫描匹配和测试范围统一见[EKF 实现](控制与定位.md#两板-fpga-ekf)。先用真实轮速＋IMU 验证，再评估 N10 校正，不重复实现已有矩阵核心。

局部 odom 保持连续，全局 map 修正独立处理；每条 TF 只指定一个发布者。Jetson 使用 FPGA 融合状态或原始测量时，避免将同源信息当成独立观测重复融合。局部子图匹配不自动代表完整 SLAM 或全局定位。

### 时间与通信

当前视频、诊断和 BX72 v1 分别使用 Jetson 6102/6103/6104。已实现的运动请求/回执与诊断共用 6103；32 字节 BX72 v1 速度包、会话/序号和 300 ms 看门狗见[数据契约](Jetson通信与接入.md#数据契约)。完整环境约束、故障输出和时间映射仍是后续扩展。

采集、估计和主机接收时间分别表达。当前 ROS Header 是接收时间，FPGA timestamp_us 是采集提交时间；时钟映射与传感器延迟在联调中测量。过期/无效测量不当作新鲜零值参与估计。

### 实时反射与导航

首版反射使用有效 N10 近距观测约束前后、横移与旋转，先完成减速/停车，无需等待扫描匹配或 EKF。阈值来自观测延迟、车体外形和实测停止表现；无效/过期观测不表示无障碍。

运动请求通过有效期与仲裁后进入速度环。具体停止、恢复和重新使能行为在协议与实车联调中验证。完整动态包络、TTC 估计和复杂故障恢复按基础演示需要逐项扩展。

定位与近障链稳定后，再做路径点、绕障和重回路线。协同模式可由 Jetson 决策；要求 FPGA＋软核独立运行的基础任务由专项部署实现。完整 SLAM、视觉识别与 AI 任务安排在当前候选运动闭环验收之后。

板级构建、约束、资源和下载统一见[BX72 README](../FPGA_ws/boards/BX72_138K_robot/README.md)与[ACG720 README](../FPGA_ws/boards/ACG720_60K_robot/README.md)。当前验证边界与交付缺口见[交接文档](handoff.md#证据与交付缺口)。

### 赛题任务与独立部署

此前赛题截图的规划摘录，正式演示及平台限制以赛事文件为准。

基础任务按 FPGA＋软核独立完成的方向实施。当前主线为 BX72 / GW5AT-138C，ACG720-60K 保留独立集成工程；资源与时序按实际部署板卡验收。Jetson 用于调试、显示、记录和允许的扩展，不能以 Jetson 联调代替基础任务独立导航证据。

| 任务 | 实现内容 | 验收证据 |
| --- | --- | --- |
| 1．多传感器感知 | OV5640 采集/显示、IMU 姿态采集与显示 | 实时画面和姿态演示、频率/连续性与物理测量记录 |
| 2．运动控制 | 前后、转向、定点旋转；四轮编码器速度闭环 | 目标/实测轮速、方向、速度响应和实际动作 |
| 3．实时避障 | 测距、障碍检测、自动减速/停车及局部绕障 | 障碍条件、响应时间、停止表现和绕障重复实验 |
| 4．自主导航 | 起终点移动、路径点到点、障碍绕过及返回路线 | 外部真值/轨迹、到点误差、重复成功与失败记录 |
| 5．视觉识别扩展 | 检测指定目标；画面显示或视觉特征不等于识别完成 | 场地目标识别与误检记录 |
| 6．智能任务扩展 | 搜索、接近与任务执行 | 识别→导航→执行的完整演示 |

此前评分摘录为 FPGA 实时感知控制 40%、稳定性 25%、自主导航 20%、创新 10%、AI 扩展 5%；据此先推进基础链路和稳定性，再做扩展。

基础任务 1 的最终显示位置和独立运行口径仍需确认：BX72 已移除 TFT、ACG720 保留 TFT，主机收包不能代替姿态显示验收。推进顺序与三人交付统一见[开发计划](handoff.md#后续开发计划)，候选身份统一见[项目状态](handoff.md#项目状态与交接)。

### 场地与定位方案

| 场地条件 | 后续方案 |
| --- | --- |
| 已知或允许预先测绘 | 验证雷达对固定地图/标志的定位，按路径点导航 |
| 短路线、局部绕行 | 有界局部定位/地图和路径跟踪，量测累计漂移 |
| 未知长路线、重复经过或严格全局精度 | 单独评估在线建图、重定位、回环及资源预算 |


完整 SLAM 若成为基础任务要求，需验证 FPGA＋软核部署。基础定位先核对编码器/IMU，再评估 N10 外参、时间和匹配质量；原始雷达点不是位姿观测。

视觉定位需可解释的几何观测、标定、采集时间与质量；颜色区域中心不直接表示距离或位姿。记录场地、障碍、路径点误差及地图要求，物理参数和算法细节归入对应工程文档。

## 公共 RTL 与研究模块

更新：2026-10-05。本文目录和命令以 `FPGA_ws` 为根；共享文档统一维护于父仓库 `docs`。本页只列保留内容；当前板级接线、控制和传感器验收以各板 README 为准。

### 保留范围

| 路径 | 用途 |
| --- | --- |
| rtl/common/cdc | 当前 BX72 使用的异步帧 FIFO |
| rtl/ethernet | 当前 BX72 使用的 UDP 接收器 |
| rtl/motor | 通用麦轮运动学、编码器、速度环及软件参数对照 |
| sim/fusion | 两板 EKF、CSM 与视频共享回归 |
| sim/motor、sim/tools | 通用电机与日志工具回归 |

2026-10-06 按 BX72 最新程序精简，旧根目录 `src/`、Pico/N10/USB 研究支线、独立相机及网络回环已移出活动工作区，原文件有本地备份，Git 历史保留。两板独立工程、板内 N10/GoRV32、固件及历史证据完整保留。

BX72 活动工程直接引用 `rtl/ethernet/eth_udp_rx_gmii.v` 和 `rtl/common/cdc/async_frame_fifo.v`。板级验证脚本调用根目录统一仿真脚本；CSM 回归已迁至 `sim/fusion/tb_v4_csm_submap.sv`。

### 回归入口

在 FPGA_ws 根目录执行，工具需已安装：

```bash
python Scripts/run_sim.py --board workspace --suite motor
```

```powershell
python Scripts/verify_workspace.py
python -m unittest discover -s sim/tools -p test_motor_log_analyzer.py -v
python Scripts/run_sim.py --board BX72_138K_robot --suite fusion
```

两板融合 HDL 使用板内 src/fusion/EKF；数学包先编译。统一仿真脚本通过 `--board` 选择各板输入，融合/网络回归的生成目录可以重新创建。
