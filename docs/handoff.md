## 证据与交付缺口

1. **位流与清单缺失。** 从构建方取得上述配套产物/证据，或在具备 Gowin 工具的环境重新构建、回归、检查时序并封存；重新构建须使用实际新哈希，不能沿用记录中的 SHA256。
2. **C++ 改写未验证。** 原 Python 参考测试不能证明新 C++ 正确；部署前在 ROS 2 Humble 环境编译、回归，并检查 Jetson 的跨进程 ROS 图和真实 UDP 数据。旧 install 可能残留 `.py` 入口。
3. **板上身份未核对。** 加载和开始验收时记录源码提交、位流哈希、User Code、接收器版本、网络配置与测试条件；其他镜像的实测不能替代该候选。
4. **物理标定和整机性能待测。** 内部 STA、收到 ACK、传输稳定均不能替代外部 IO、机械响应或定位验收。ACK 仅表示入队，ROS Header 是接收时间，FPGA 采集时间尚未映射。

### 第一轮共同交付

1. A 提供加载身份/哈希与通信结果，B 提供动作/计数/停止记录，C 提供同时间段的日志与目标/实测曲线。
2. 汇总每项通过/失败、环境、配置和故障触发时刻；一次只调整有证据支持的参数或逻辑。
3. 三人确认当前候选的悬空并发、断命令停车和断网恢复结果，再安排低速落地；不要仅凭回执或视频判断动作正确。

### 下一共同里程碑：当前候选的遥控并发与停车

1. 位流 SHA256、板上身份、源码提交及接收脚本对应实际验收候选清单；不得用其他镜像的测试结果代替当前候选验收。
2. 四轮悬空下检查前后、横移、斜向、正反旋转及零速度；同时记录请求速度、目标/实测轮速、编码器、IMU、回执与视频。
3. 验证松键、窗口失焦、客户端关闭、网关退出、命令断流及实际断网后的停止；记录触发到 PWM 停止/物理停转的时间。
4. 重连后确认相位训练、零速握手及重新使能；区分自动恢复与人工刷新邻居等操作。
5. 保存测试条件、视频/原始日志、错误/序号缺口/源丢弃统计和失败记录；入队回执不计作机械闭环达到目标。

门限和通过标准按已有脚本及实测条件记录。内部 STA 通过不代表停止距离、测速比例或外部 IO 时序通过。

### 已实现接口与待标定项

协议为 BX72 v1，大端 32 字节速度包 type=3/4，FPGA 5000、Jetson 6103；本机约 50 Hz 更新请求、Jetson 约 20 Hz 转发、FPGA 非零速度看门狗约 300 ms。详细新鲜度/会话和恢复行为见[数据契约](Jetson通信与接入.md#数据契约)。

轮序 A/B/C/D=FL/FR/RL/RR，映射 0xD2、电机反向 0xB、编码器反向 0xA。当前 122880 count/输出轮圈、98 mm 轮径、160/196 mm 轴距/轮距仍需物理核验。ROS Header 为接收时间，FPGA timestamp_us 为采集提交时间；定位前需确定时钟映射、外参、噪声和唯一 TF 发布者。

### 后续顺序

候选实板并发/停车 → 整圈计数及传感器核对 → 低速落地负载 → ROS `/cmd_vel` → 编码器/IMU 定位 → N10 校正 → 路径点/绕障 → 整机长时验收。近障减速/停车可在低速控车后独立推进。

基础任务独立部署按[赛题规划](README.md#赛题任务与独立部署)执行。ACG720 先处理自身 DDR 负时序路径，不能使用 BX72 的放行结论。
