## 2026-09-30 优化与 2026-10-01 融合

原两板的行缓存保存 0、2、…、798 号输入像素，400×16 的两 bank 合用 800×16 RAM，使 TFT 左半屏保持完整横向视野；行结束仍等待消费到 x=799，不改变 DDR/网络完整帧。行缓存 BSRAM 从 2 降为 1。ACG720 仍使用该通路，BX72 后续已移除 TFT 与行缓冲。

运动学和速度环采用有符号位宽约束与迭代运算，保持目标快照、同比例限速、停机和历史语义。两板当前速度环是 FL/FR 与 RL/RR 两组独立共享引擎，组内历史分开保存、结果原子提交；当前功能回归保留，依赖旧浮点/RTL 备份的等价脚本已移除。

七状态 EKF 及完整协方差、IMU/N10 时间对齐加入后资源提高，2026-09-30 电机阶段资源数字不再代表当前整板。融合模块已搬迁到各板 src/fusion/EKF，迁移内容哈希相同，共享数学包需先编译。[EKF 文档](robot_fpga_ekf.md) 保留算法、寄存器及 640 个数值向量的验证范围。

ACG720 的雷达位图仍是 400×480 单 bit、约 12 BSRAM；18 bit 打包最多可能省一块，须验证 true-dual-port、读改写与跨域碰撞，尚未实施。BX72 已删除显示位图。BX72 现已完成网络取帧与 TFT 解耦；ACG720 的网络读节拍仍依赖 TFT。

## 2026-09-28 DDR PHY 调查

以下仅为历史调查：60B、DDR IP 5.8、x16、1 rank、8 bank、14 row、10 column、CL6/CWL5；板载 Micron MT41J128M16 2 Gb 的完整速度/封装后缀未确认。当时使用 400 MHz 内存 / 100 MHz UI、1:4，当前 ACG720 已是 200/50 MHz。

| 历史目标 | setup / hold 违例端点 | 最差 setup / hold / recovery（ns） |
| --- | --- | --- |
| 完整目标，400/100 MHz | 72 / 2 | -1.937 / -0.644 / -2.185 |
| DDR 单独目标，400/100 MHz | 56 / 22 | -2.594 / -0.640 / -1.551 |
| DDR 单独实验，333.333/83.333 MHz | 3110 / 22 | -2.094 / -0.643 / -3.383 |

当时更换 333 MHz IP/PLL 的实验增加相关时钟跨域检查，未移入主工程，未做实板校准与读写验证。原独立 experiments 目录已不在本工作区，本次没有恢复备份，也不继续引用它作为现有重跑入口。

重点路径为 DDRDLL STEP、DQS HOLD/CALIB 和跨域 RESET/recovery；普通布局布线完成并不等于 STA 收敛。历史厂商问题草稿集中为：

1. 60B 对应 IP 的参考、memory、UI 域应如何约束；5A25K 或 138K 示例的异步分组是否适用于此器件/IP？哪些内部跨域由 IP 保证？
2. STEP、HOLD、CALIB 与复位路径是否有明确版本、放置或官方约束要求？
3. Bank 9 HCLK、PLL_B、DDRDLL 放置及 PG484 封装管脚是否满足推荐连接？
4. DDR 实物完整后缀、CL/CWL、命令时序和上板校准记录是否匹配？

原参考为 [高云 DDR3 页面](https://www.gowinsemi.com/en/support/ip_detail/14/) 和 [IP 用户指南](https://www.gowinsemi.com/upload/database_doc/2009/document/696a8c052f84e.pdf)。问题草稿没有代表用户向外部发送。BX72 后续有 138C/IP6.1 与 138K 原厂分析模型依据，见其板级文档，不能直接作为 ACG720/60B 的结论。
