# ACG720-60K 四轮麦轮机器人后续开发计划

更新：2026-09-23。本计划以三个独立 Git 工作树的当前文件为依据：父仓库 `FPGAGowin2026`、`FPGA_ws` 和 `ros_ws`。已有未提交改动及独立 25K 工程删除保持原状；带 25K 名称的 N10 实验和独立 138K 专项代码保留，但均不是本车开发目标。计划不表示相关功能已实现，也不把旧差速工程或参考工程的历史结果计入当前 60K 实车验收。

用户提供的赛题页将摄像头和姿态实时显示、带编码器闭环的前后/转向/定点旋转、测距自动减速停车、起终点及路径点导航列为四项基础任务；评分重点依次为 FPGA 实时感知控制 40%、系统稳定性 25%、自主导航 20%、创新设计 10%、AI 扩展 5%。因此先做可实测的基础任务与稳定性，再开展视觉识别和智能任务扩展。赛题中“仅使用 FPGA＋软核 CPU 即可完成”的含义须以正式规则确认：若基础任务必须脱离 Jetson 演示，需另设计 60K 上的轻量导航能力；不恢复已删除的独立 25K 工程或旧路径代码。

## 关键依赖和执行顺序

```text
P0 验收基线
 ├─→ P1 接线/电气/停机门槛 → P2 单轮辨识与闭环 → P3 四轮运动学与里程计
 ├─→ P4 新通信契约与60K链路 ────────────────→ P6 ROS四轮适配
 └─→ P5 IMU660RC/OV5640/TFT/测距接入 ────→ P6 ROS四轮适配
P1＋P2＋P4＋测距实测 → P7 故障处理与本地反射
P3＋P5＋P6＋P7 → P8 整机联调 → P9 实车/赛题验收
```

P4 的协议定义和主机模拟可与 P1/P2 并行；P5 的资料核对、TFT 彩条及无电机摄像头试验也可并行。首次电机带电前，必须具备限流和可独立切断电机电源的手段；自主行驶前须通过 P7 的故障注入。各阶段完成与否按下述交付物和实测结果判断，不按源码数量或历史完成度百分比判断。

## P0｜验收口径与实验基线

- **前置条件：** 使用当前三个工作树，分别记录仓库 commit、未提交差异和被忽略的关键构建产物；不做提交、清理或改写。
- **具体任务：** 固定主板 `GW5AT-LV60PG484AC1/I0`、FL/FR/RL/RR 轮序及 x 前、y 左、z 上坐标；建立参数来源表。为轮速误差、停车时间/距离、里程误差、通信延迟、传感器年龄、帧率和长时稳定性定义试验条件与验收阈值，待实测前不使用占位值签收。
- **交付物与验收标准：** 有版本和负责人、指标、量测方法、原始记录位置的验收矩阵；赛题四项基础任务各有独立演示与复现步骤。
- **验证方法与所需数据：** 对照源码、实物铭牌、赛题完整规则及工作树清单评审。
- **主要风险/阻塞：** 规则中 FPGA＋软核 CPU 与 Jetson 的使用边界尚待正式解释；被 Git 忽略的 `build/` 证据需单独保存。

## P1｜板级接线、电气核对和无负载点亮

- **前置条件：** ACG720-60K、AT8236 驱动板、四电机/编码器、限流电源和可独立断电的停机手段齐备。
- **具体任务：** 对照实际线束逐项核查 FPGA 球位→连接器→AT8236 IN1/IN2→电机与编码器 A/B→物理轮位。测 GPIO bank、驱动输入和编码器输出电平，确认共地、上拉/开漏、供电顺序、电流能力及驱动真值表。无电机负载先检查时钟、复位、UART、PWM 和失能波形。
- **交付物与验收标准：** 签认的接线/供电/通道表和波形；无 5 V 直接误入不兼容引脚、无管脚冲突，复位/失能时四通道输入符合实测的驱动停机状态。
- **验证方法与所需硬件/数据：** 板卡和驱动原理图、万用表、示波器或逻辑分析仪、电源电压/电流记录。
- **主要风险/阻塞：** 当前 GPIO0 CST 只是候选预留，外部 I/O 延迟未约束；缺接线表或器件电平资料则不进入带电机试验。

## P2｜电机辨识与四轮速度闭环标定

- **前置条件：** P1 通过；轮子架空固定且可限流、断电。
- **具体任务：** 逐轮低占空比点动，确定 CH→轮位、驱动方向及编码器 A/B 相序，分别设置输出映射、输入映射、电机和编码器极性。手转输出轴正反多圈测四倍频每圈计数；测有效滚动周长、速度/电流阶跃、启动死区、换向和失能滑行。按 `round(周长_mm / 每圈计数 × 65536)` 设置测速比例，逐轮整定 PI 后再测四轮同时运行。
- **交付物与验收标准：** 四轮映射、极性、计数/圈、有效周长、PI 和速度响应原始数据；正负命令/计数符号一致，无持续反向调节或明显振荡，误差与停车表现满足 P0 冻结阈值。
- **验证方法与所需硬件/数据：** 计数日志、外部测速或标记视频、电压/电流记录，按单轮→四轮、架空→着地低速递进；对比目标/实测轮速与 PWM。
- **主要风险/阻塞：** 当前 `COUNTS_PER_REV_CANDIDATE=0`，`MM_PER_TICK_Q16=168` 和 PI 是占位；编码器所在轴、减速比与真实计数未知。

## P3｜麦轮运动学与里程计

- **前置条件：** P2 四轮符号及轮速可信，核实 X 型滚子安装和地面接触。
- **具体任务：** 验证前后、横移、正反旋转的四轮符号矩阵；实测轴距 A、轮距 B 和有效 `L=(A+B)/2`。检查协调限速、斜坡、车体 `vx/vy/wz` 及不同载荷和地面下的打滑，确定车体状态的时间和有效性语义。
- **交付物与验收标准：** 符号矩阵、几何标定报告、FK/IK 与外部真值对照；基础动作方向正确，重复运行的直行、横移与旋转误差满足 P0 阈值。
- **验证方法与所需硬件/数据：** 地面标线、视频或外部定位，多速度/载荷重复试验，保存四轮计数和外部位姿。
- **主要风险/阻塞：** 当前 A=180 mm、B=200 mm 是估值；麦轮横移和旋转受地面、载荷及滚子状态影响。

## P4｜FPGA—Jetson 新协议与 60K 网络链路

- **前置条件：** P0 固定轮序、单位和时间语义；取得 60K PHY/RGMII/时钟资料。
- **具体任务：** 将旧差速 v1 线格式保留为历史对照，定义四轮新版本：`vx/vy/wz`、四轮计数/速度、启动/会话 ID、序号、命令有效窗口、硬件时间、有效性与故障原因。规定字节序、范围、完整性校验、包长、端口、队列优先级和拒绝/恢复规则；先做双端黄金向量，再将以太网基础 RTL 与电机顶层集成到 60K。
- **交付物与验收标准：** 冻结的数据契约、交叉编解码与端到端仿真、60K 网络工程及实板抓包。坏包、重复/乱序/过期包不刷新运动许可；网络拥塞不阻塞本地停机。
- **验证方法与所需硬件/数据：** 错误注入、重启/断网/重连、Wireshark 抓包及 CDC/FIFO 测试；Jetson、网线、PHY 原理图。
- **主要风险/阻塞：** 当前 60K 电机工程仍是 UART 顶层；历史网络 RTL 和 ROS v1 协议尚未接入本车。

## P5｜IMU660RC、OV5640/TFT 和近距感知

- **前置条件：** P1 完成相应供电与引脚核对；IMU660RC 已明确为 LSM6DSV16XTR、SPI 接口；摄像头与屏幕按用户指定参考工程配置。
- **具体任务：** IMU 完成 SPI 识别/初始化、原子采样、单位换算、零偏与安装轴向标定、姿态计算、采样时间和无效数据处理。OV5640 按[摄像头与 TFT 接入基线](../FPGA_ws/docs/acg720_60k_ov5640_tft.md)实施 800×480 RGB565、DDR3 帧缓存和 5 寸 TFT 显示；在支持 GW5AT-60B 的最新可用 Gowin EDA/IP Generator 中重新生成实际所需 PLL、DDR3/FIFO IP。确定一种可实物验证的超声波、ToF 或激光测距模块，记录视场、盲区和数据年龄。
- **交付物与验收标准：** IMU 静止/定轴转动数据和姿态显示；TFT 彩条、DDR3 校准/读写、OV5640 实时画面及姿态叠加的逐级证据；测距有效性与距离记录。显示持续稳定，错误/过期数据标为无效，不继续显示成实时值。
- **验证方法与所需硬件/数据：** SPI/SCCB/DVP 逻辑分析、图卡和运动场景、DDR3 校准/帧计数、屏幕视频、IMU 静止与转动记录；模块接线、板卡/TFT/DDR3 资料。
- **主要风险/阻塞：** 当前没有 IMU660RC 驱动或本车完整摄像头链路。参考 CST 文件头为 138K，未启用的 `camera_pll.ipc` 指向 25K；旧 IP/码流不直接复用为当前 60K 结果。

## P6｜ROS 2 四轮麦轮适配

- **前置条件：** P3 的轮序/几何和 P4 协议冻结，IMU 有效性语义明确。
- **具体任务：** 使 `fpga_gateway` 发送 `/cmd_vel` 的 x/y/wz 三分量、解码四轮遥测，发布四轮关节和含横向速度的轮式里程计；同步更新模拟器、bringup 配置、测试及诊断。指定 `odom→base_link` 与 `map→odom` 的唯一发布者，在 EKF 中处理轮速与 IMU 的相关性和时间戳。
- **交付物与验收标准：** 四轮 ROS 包与配置、主机闭环及实板联调记录；横移、转向和停车命令往返一致，TF 无重复发布者，断链或过期测量不作为新数据持续发布。
- **验证方法与所需硬件/数据：** 协议单测、ROS launch、bag 回放、TF 检查、抓包及 P2/P3 标定数据。
- **主要风险/阻塞：** 当前网关只用左右轮速度算差速里程计，忽略 `/cmd_vel.linear.y`；旧 YAML 的半径、轮距、每圈计数不是四轮实测值。

## P7｜故障处理与本地实时反射

- **前置条件：** P1 硬件停机路径、P2 实测制动/滑行、P4 命令许可语义和 P5 测距覆盖到位。
- **具体任务：** 先满足赛题基础减速/停车：有效近距观测直接作用于 FPGA 本地限速/停车。再实现 Watchdog、故障分类、仲裁和最终 Motor Output Gate；为编码器异常、超速、传感器过期、失联、急停和电源故障建立处置及恢复表。测得保守延迟和减速度后再设前后、横移、旋转的安全包络。
- **交付物与验收标准：** 故障真值表、保护 RTL、仿真和实板注入记录；复位/未配置/失联时输出按定义关闭或受控制动，解除故障后需显式重新使能和新鲜命令，不能自动恢复旧速度。
- **验证方法与所需硬件/数据：** 断网、坏包、编码器拔线、传感器超时、急停及复位注入；同步记录距离、请求/允许速度、输出门控、电流和停止距离。
- **主要风险/阻塞：** PWM 归零可能只是滑行，不能代替制动证明；测距盲区、延迟和地面条件决定保护边界。同 FPGA 看门狗不覆盖整体失钟/掉电。

## P8｜60K 整机联调

- **前置条件：** P3～P7 各自通过，使用确定的管脚、IP、参数和协议版本。
- **具体任务：** 按通信空载→IMU/测距→TFT/摄像头→架空电机→着地低速逐项合并；重新检查 I/O bank、时钟/复位、CDC、DDR3 与网络队列带宽、资源、外部 I/O 约束和 P&R/STA。保存同一时间轴的命令、轮速、风险、输出许可和故障记录。
- **交付物与验收标准：** 可复现的单一 60K 整机工程、构建报告和码流哈希、板级联调日志；全功能时序无未解释违例，显示/上传拥塞不影响电机闭环与本地保护。
- **验证方法与所需硬件/数据：** 隔离构建、RTL/板级测试、抓包、逻辑分析、ROS bag、故障注入及长时运行。
- **主要风险/阻塞：** 电机工程 55.824 MHz 的既有 Fmax 只适用于原工程；新 IP 和整机合并必须重新验收。

## P9｜实车与赛题任务验证

- **前置条件：** P8 通过，台架及低速地面故障处理已验证。
- **具体任务：** 分级测试静止、单轴低速、组合速度、前后/转向/定点旋转、近障碍减速停车、起终点移动、绕障和路径点导航；每项重复并保存外部真值。扩展任务再接入 Jetson 目标识别与指定目标搜索/接近，平台允许性按正式赛题规则确认。
- **交付物与验收标准：** 四项基础任务的独立演示和原始日志、视频、场地/载荷/地面条件、失败复盘及长时稳定性报告；所有动作和故障响应满足 P0 预定阈值，恢复后不沿用旧命令。
- **验证方法与所需硬件/数据：** 隔离场地、地面标记或外部定位、可控障碍、不同电量/载荷及多次重复试验。
- **主要风险/阻塞：** 麦轮横移误差、地面打滑、制动距离和传感器盲区可能随条件变化；一次演示不能代表稳定性。

## 最近两周任务（2026-09-23 至 2026-10-06）

1. **第 1～2 天：** 建立 P0 的工作树/构建证据索引、参数来源表与赛题四任务验收表；核实基础任务是否必须脱离 Jetson。
2. **第 1～4 天：** 收齐 GPIO0、AT8236、编码器、电源和急停接线，完成 P1 电平与无电机负载波形核对。
3. **第 2～6 天并行：** 按指定参考工程核对 OV5640、DDR3、TFT 的 60K 管脚和实际启用 IP；制定新 IP 再生成清单与 TFT 彩条/DDR3 分段验收。核对 IMU660RC SPI 接线和安装轴向。
4. **第 4～9 天：** 架空逐轮测 CH→轮位、正反极性、AB 相序与输出轴四倍频计数/圈；保存原始数据。
5. **第 6～12 天：** 单轮低速阶跃、电流和失能滑行测试，初步整定 PI；仅在 P1/P2 门槛满足后进行低速地面基本动作。
6. **第 1～12 天并行：** 冻结新 UDP 契约草案和双端黄金向量；选定基础避障所用测距器件及接口。
7. **第 12～14 天：** 汇总四轮、IMU/TFT 和测距接入阻塞，更新后续排期。两周交付重点是可签认的接线、器件/IP 配置和实测标定数据，不把无板测功能标为完成。
