本文为独立学习资料，其学习安排不是机器人开发阶段；不据此增加软核 SLAM 或其他主线功能。 当前设计与工作区职责以 [系统总体方案](系统总体方案.md) 为准：Jetson Orin Nano＋四轮麦轮＋FPGA 实时反射层，FPGA_ws 保存当前 RTL、板级固件与回归源，生成缓存按需重建，gowingame 已退役。项目状态见[当前记录](project_status_20261005.md)，本文学习内容不作为功能验收证明。

> 适用对象：没有数字电路和 Verilog 基础，或只会照着例程修改代码的学习者

> 主要目标：能够在约 2 小时内独立完成一类 FPGA 国测题，得到正确仿真波形，并能解释自己的设计

# 一、先说结论

这类 FPGA 国测并不是要求你做一个特别庞大的工程，而是考察你能否在有限时间内完成下面这件事：

> 把一段中文需求拆成寄存器、组合逻辑、计数器、状态机和存储器，再用 Verilog 写出来，通过 Testbench 验证每一个时钟周期的行为。

国测最重要的五项能力是：

1. **时序逻辑**：知道寄存器在第几个时钟沿更新。
2. **计数器**：能准确实现持续 N 拍、每 N 拍进位和单周期脉冲。
3. **状态机**：能把交通灯、密码锁、电梯等文字需求拆成几个状态。
4. **位宽与符号**：不会把 4 位二进制 `1111` 一律当成十进制 15。
5. **仿真调试**：能在波形中找到“第一个出错的时钟沿”。

现阶段不需要优先学习：

- DDR
- PCIe
- 高速串行收发器
- AXI 总线的大量细节
- 图像处理算法
- UVM
- HLS
- 复杂时序约束和高级时序收敛

这些内容以后可能对主赛项目有用，但不是解决这批国测题的前置条件。

# 三、历年题目考点分析

## 3.1 2019 年

### 题目一：有符号累加器

要求连续接收 4 个有效的 4 位有符号数，每组计算完成后输出 6 位有符号结果，并拉高一个时钟周期的 `o_ready`。

考点：

- 4 位补码表示 -8～+7
- 符号扩展
- 累加结果的位宽
- `valid` 有效时才接收
- 每 4 个有效数据为一组
- `o_ready` 单周期脉冲
- 输出本组结果的同时能够衔接下一组输入

### 题目二：脉冲计数

在两个计数使能上升沿之间统计有效脉冲，并根据脉冲数量输出编码结果。

考点：

- 上升沿检测
- 时间区间的开始和结束
- 计数器
- 结果分档编码
- 完成脉冲只持续一拍
- 边界值属于哪一档

### 题目三：带回退的同步 FIFO

FIFO 深度为 8、数据宽度为 8 位，包含读写、满、空和回退功能。

考点：

- 存储数组
- 读指针和写指针
- 有效数据数量
- `full` 和 `empty`
- 满时禁止写，空时禁止读
- 读写同时发生
- 回退期间禁止普通读写
- 回退不能破坏 FIFO 边界

### 题目四：非重叠序列检测

检测序列 `1101`，检测成功后产生标志，并对成功次数进行计数。

考点：

- 移位寄存器或状态机
- 非重叠检测
- `valid` 控制
- 检测成功脉冲
- 计数器饱和，达到最大值后保持不变

## 3.2 2020 年

### 题目一：BCD 加法器

两个 4 位二进制输入相加，输出十进制结果的十位和个位 BCD。

考点：

- 组合逻辑
- 加法结果位宽
- 二进制与 BCD 的区别
- 十位和个位分离
- 复位行为

### 题目二：阶乘计算

计算 `n!`。如果计算尚未完成时 `n` 改变，不能打断前一次计算，要在前一次完成后继续处理新的任务。

考点：

- 多周期运算
- `0! = 1`
- 忙碌状态 `busy`
- 当前任务和等待任务
- 输入变化检测
- 结果何时更新

### 题目三：双序列检测

输入序列为 `111000` 或 `101110` 时输出有效，`valid=0` 时暂停接收，但保留之前已经输入的历史。

考点：

- 移位寄存器
- 同时比较两个目标序列
- `valid` 暂停
- 历史信息保持
- 输出时机

### 题目四：有符号累加器

与 2019 年题目一基本相同，说明有符号数、分组接收和单周期结果脉冲是高频基础考点。

## 3.3 2023 年

### 题目一：电梯控制

40 层电梯每个时钟移动一层，2～9 层正常情况下不可作为目标，检测到紧急按键上升沿时才允许前往，同时还要判断人数和重量是否超限。

考点：

- 当前楼层寄存器
- 目标楼层锁存
- 大小比较
- 每拍加一或减一
- 非法目标过滤
- 按键上升沿检测
- 组合报警逻辑

### 题目二：六位固定分组检测

每六位固定为一组检测 `011010`。即使第一位已经错误，仍然必须接收本组剩余五位，第七位才是新一组的开始。

考点：

- 固定长度分组
- 非重叠检测
- 6 位移位寄存器
- 0～5 位计数器
- 收完后下一拍输出 `match` 或 `not_match`

## 3.4 2024 年

### 题目一：12 小时制 BCD 电子钟

从 `00:00 am` 开始，输出小时、分钟、秒的两位 BCD，并支持使能和高有效复位。

考点：

- 模 10、模 6、模 12 计数器
- BCD 级联进位
- `59→00`
- `11:59:59→00:00:00`
- 上午/下午翻转
- 复位优先于使能

### 题目二：游戏机计费

包含关机、普通、畅玩和一次性体验模式，支持预付费、续费、余额不足报警和体验时间限制。

考点：

- 状态机
- 每状态不同费率
- 充值和扣费优先级
- 防止余额下溢
- 体验次数限制
- 体验持续 5 拍
- 体验结束自动返回普通模式

## 3.5 2025 年

### 题目一：串行电子密码锁

支持 4 位密码输入、退格、确认、错误次数、10 拍开锁和 50 拍安全锁定。

考点：

- 输入缓冲区
- 输入长度
- 写入、删除和清空
- 密码比较
- 重试次数
- `IDLE/UNLOCK/LOCKED` 状态机
- 开锁计时器
- 锁定计时器
- 锁定期间屏蔽所有按键

### 题目二：带冷却中断的交通灯

主干道按绿 10 拍、黄 3 拍、红 10 拍自动循环。行人按钮可以在绿灯期间提前触发黄灯，但触发后进入 18 拍冷却。

考点：

- 红、绿、黄状态机
- 状态持续时间
- 按钮只在指定状态有效
- 类似中断的提前跳转
- 独立冷却计时器
- 冷却期间忽略按钮

# 四、用最简单的话认识 FPGA

可以把 FPGA 想象成一块巨大的数字乐高底板。Verilog 不是在写普通软件步骤，而是在描述要搭出什么电路。

- **组合逻辑像计算器**：输入一变，输出跟着重新计算。
- **寄存器像小本子**：只有时钟上升沿到来时才把新值写进去。
- **计数器像数圈**：每来一次有效时钟就增加一次。
- **状态机像游戏关卡**：系统在红灯关、绿灯关或黄灯关中切换。
- **FIFO 像排队买饭**：先进入的数据先出去。
- **`valid` 像举手说“这次输入是真的”**。
- **`ready` 像举牌说“这次结果已经完成”**。
- **reset 像重新开机**：把系统恢复到题目要求的初始状态。

最需要记住的一句话：

> Verilog 描述的是并行工作的硬件，不是从上到下依次执行的普通程序。

# 六、每天和每周怎么学习

## 6.1 每天 100 分钟或 120 分钟模板

| 环节 | 100 分钟版 | 120 分钟版 | 目的 |
|---|---:|---:|---|
| 回忆昨天内容 | 10 分钟 | 10 分钟 | 检查是否真的记住 |
| 学一个新知识点 | 20 分钟 | 20 分钟 | 每天只增加一个主要概念 |
| 写一个小模块 | 25 分钟 | 30 分钟 | 把知识变成代码 |
| Testbench、波形和纠错 | 35 分钟 | 40 分钟 | 形成调试能力 |
| 错题记录 | 10 分钟 | 10 分钟 | 防止下次重复犯错 |
| 删除部分代码后默写 | 当天省略 | 10 分钟 | 检查是否脱离示例 |

如果当天还没有正式学习 Testbench，就把“Testbench、波形和纠错”时间用于手动画真值表、时间轴和人工检查；不要提前使用尚未学习的语法。

## 6.2 每周六天模板

- **第 1 天：理解**——学习本周新概念，手动画图。
- **第 2 天：模仿**——照着一个正确例子写小模块。
- **第 3 天：独立**——不看例子重新写。
- **第 4 天：扩展**——增加复位、使能、暂停或边界条件。
- **第 5 天：验证**——自己写完整 Testbench。
- **第 6 天：考试**——限时从空文件开始完成。
- **第 7 天：休息或只整理错题**。

学习不是“视频看了多少”，而是：

```text
写模块 → 仿真 → 找到第一处错误 → 修改 → 加入新边界测试
```

# 七、20 周详细学习路线

## 第 0 阶段：仿真环境启动营，3 天，不计入 20 周

零基础学习者必须先让工具跑起来。可以使用已经安装的 Vivado；如果学校统一使用其他 FPGA 仿真工具，也可以完成同样的步骤。前 8 周只做行为仿真，不需要开发板。

### 开始前先走工具决策树

```text
电脑已经安装并能打开学校/队伍统一的工具？
├─ 是 → 直接进入第 0-1 天
└─ 否
   ├─ 学校或队伍规定了版本？
   │  ├─ 是 → 获取并安装完全相同的版本和对应器件支持
   │  └─ 否 → 先确认比赛开发板上的 FPGA 型号，再选择支持该器件的版本
   └─ 只想先学行为仿真？
      └─ 仍可安装 Vivado 仿真环境，或在老师指导下使用 Icarus Verilog + GTKWave
```

安装前必须向队伍或老师确认四件事：

1. 比赛或课程统一使用什么软件、什么版本。
2. 开发板上的 FPGA 厂商和完整器件型号是什么。
3. 安装器中是否选择了对应器件系列支持。
4. 赛前断网环境下，软件能否离线打开、编译和运行仿真。

仓库个人代码提到曾在 Vivado 2017.4 中仿真，但这不代表你的开发板一定适合 2017.4。软件版本应服从实际器件和队伍环境，不要只因为仓库提到某个版本就盲目安装。

创建 Vivado 工程时会要求选择器件或开发板：

- 已知开发板型号且已安装 Board Files：从 Boards 中选择对应开发板。
- 只知道 FPGA 芯片型号：从 Parts 中按照完整器件型号选择。
- 暂时只做行为仿真且还没有开发板：可以选择安装器中已有的任意受支持器件，但在进行综合、生成比特流前必须改成真实器件。
- 不知道器件型号：查看开发板说明书、芯片表面丝印或询问队伍负责人，不能凭外观猜。

如果软件尚未安装或无法确认器件，第 0 阶段暂时标为“阻塞”，先解决工具问题，不要直接跳到后面的真题。

### 第 0-1 天：确认工具并建立练习目录

1. 确认电脑上能打开 Vivado 或学校指定的 Verilog 仿真工具。
2. 在自己方便的位置建立 `fpga_practice` 目录。
3. 在目录中按周建立 `week01`、`week02` 等子目录。
4. 每一道题至少分成设计文件 `xxx.v` 和测试文件 `tb_xxx.v`。

### 第 0-2 天：创建第一个工程

以 Vivado 为例：

1. 选择创建新的 RTL Project。
2. 添加一个 Design Source，文件名为 `hello_and.v`。
3. 添加一个 Simulation Source，文件名为 `tb_hello_and.v`。
4. 将测试模块设置为仿真顶层。
5. 选择 Run Simulation → Run Behavioral Simulation。
6. 在波形窗口加入输入和输出信号。
7. 使用缩放功能看到输入变化与输出变化。

最小设计文件：

```verilog
module hello_and(
    input  wire a,
    input  wire b,
    output wire y
);
assign y = a & b;
endmodule
```

最小测试文件：

```verilog
`timescale 1ns/1ps
module tb_hello_and;
reg a, b;
wire y;

hello_and dut(.a(a), .b(b), .y(y));

initial begin
    a = 0; b = 0;
    #10 a = 0; b = 1;
    #10 a = 1; b = 0;
    #10 a = 1; b = 1;
    #10 $stop;
end
endmodule
```

### 第 0-3 天：完成环境验收

只有下面各项全部完成，才进入第 1 周：

- [ ] 工程能够成功编译
- [ ] 行为仿真能够启动
- [ ] 波形中能看到 `a`、`b`、`y`
- [ ] 只有 `a=1,b=1` 时 `y=1`
- [ ] 知道 Design Source 与 Simulation Source 的区别

# 九、陌生题八步解题法

## 第一步：原样抄模块接口

模块名、端口名、输入输出方向和位宽不能自己修改。

## 第二步：圈出关键词

重点寻找：

- 上升沿还是下降沿
- 高有效还是低有效
- 哪个信号表示输入有效
- 输出是一拍还是多拍
- 立即发生还是下一拍发生
- 满、空、余额不足时怎么办
- 两个事件同时发生时怎么办

## 第三步：列出需要记忆的量

凡是要记住上一次结果的量，一般需要寄存器，例如：

- 当前状态
- 当前楼层
- 累计结果
- 已接收数据个数
- 输入长度
- 重试次数
- 计时器
- FIFO 指针

## 第四步：计算位宽

位宽不能凭感觉。

- 计 0～7 需要 3 位
- 计 0～9 需要 4 位
- 计 0～49 需要 6 位
- 四个 -8～+7 相加需要覆盖 -32～+28

## 第五步：画时间轴

例如开锁持续 10 拍：

```text
confirm: ___|‾|________________
unlock : ____|‾‾‾‾‾‾‾‾‾‾|____
计数值 :      0 1 2 3 ... 9
```

必须提前决定计数器为 0 的周期是不是第一拍。

## 第六步：写事件优先级

例如密码锁：

```text
if reset
else if locked
else if unlock
else if confirm
else if backspace
else if key_valid
else hold
```

## 第七步：写 Verilog

统一要求：

- 一个寄存器尽量只在一个时序块中赋值
- 时序逻辑使用 `<=`
- 组合逻辑使用 `=`
- 组合逻辑先给默认值
- 单周期脉冲每拍先清零
- 不在可综合模块中使用 `#10` 一类仿真延迟

## 第八步：主动攻击自己的设计

检查：

- 最后一拍同时复位怎么办
- `valid` 突然变 0 怎么办
- 按钮一直保持高怎么办
- 余额不够扣怎么办
- 计数器达到最大值怎么办
- 两个输入同时有效怎么办
- 状态切换和充值同时发生怎么办

# 十、仿真与边界检查清单

## 10.0 统一 PASS 判定标准

不要只凭“波形看起来差不多”宣布通过。一道题只有同时满足下面条件才记为 PASS：

1. 设计文件和 Testbench 编译无错误；所有警告都读过并确认不会影响功能。
2. 题面内嵌 Benchmark 或本地配套测试能够完整跑到 `$stop`，没有卡死。
3. 自己为复位、最小值、最大值、暂停和时间边界建立测试，错误计数为 0。
4. 复位释放后，关键输出不出现无法解释的 `X` 或 `Z`。
5. 所有单周期脉冲恰好持续 1 拍；所有 N 拍状态恰好持续 N 拍。
6. 不存在同一寄存器多驱动、组合锁存或把普通按键当时钟等结构性问题。
7. 保存本次测试记录：源代码、Testbench、仿真日志和至少一张关键波形截图。

每个测试先填写预期表，再运行仿真：

| 测试编号 | 输入在哪一拍被采样 | 预期输出从哪一拍变化 | 预期值 | 持续几拍 | 实际结果 | PASS/FAIL |
|---|---:|---:|---|---:|---|---|
| T01 |  |  |  |  |  |  |
| T02 |  |  |  |  |  |  |

推荐在 Testbench 中维护错误计数：

```verilog
integer error_count = 0;

// 在约定的检查时刻执行
if (actual !== expected) begin
    error_count = error_count + 1;
    $display("ERROR: actual=%b expected=%b", actual, expected);
end

// 全部测试结束时执行
if (error_count == 0)
    $display("PASS");
else
    $display("FAIL: %0d errors", error_count);
```

判断“持续 N 拍”时，不要靠波形宽度猜。给每个时钟上升沿编号，记录信号为高的周期编号；只有连续编号数量正好为 N 才算通过。

## 10.1 复位

- [ ] 复位有效电平是否看对

## 10.4 符号与位宽

## 10.6 代码质量

# 十三、不要直接照抄个人解答

仓库中的 `Personal_Solution` 不是官方答案，而且部分代码存在不适合初学者模仿的写法：

- 一个寄存器在多个 `always` 块中赋值
- 时序逻辑大量使用阻塞赋值
- 使用 `always @(posedge set)`，把普通控制信号当成时钟
- 组合逻辑没有覆盖所有分支
- 使用 `+1` 等方式临时修补波形
- 部分文件自己标注了“错误”或“多延后一个周期”

推荐模板原则：

```text
组合逻辑：always @(*) + 阻塞赋值 =
时序逻辑：always @(posedge clk...) + 非阻塞赋值 <=
同一个寄存器：只在一个地方赋值
按键、valid、set：作为数据或使能，不随便作为新时钟
```

正确使用参考答案的方法：

1. 先自己画结构。
2. 自己写第一版。
3. 自己完成仿真。
4. 再看参考答案用了什么思路。
5. 只吸收结构，不复制可疑写法。

# 十八、常用概念小词典

## bit

一根只能表示 0 或 1 的数字信号线。

## bus 总线

多根 bit 组合在一起，例如 `[7:0]` 表示 8 位总线。

## BCD

每一个十进制数字用 4 位二进制表示。例如十进制 59 的 BCD 是 `0101_1001`。

## 补码

数字电路中表示有符号整数的常用方式。4 位补码范围是 -8～+7。

## 组合逻辑

输出只由当前输入决定，不保存历史。

## 时序逻辑

包含寄存器，能够保存历史，通常在时钟边沿更新。

## 寄存器

在时钟到来时保存数据的电路。

## FSM

有限状态机。把系统划分成有限个状态，并规定状态之间如何切换。

## valid

表示当前输入是否有效。`valid=0` 时通常不能接收这次数据。

## ready/done/match

表示结果已经准备好、任务已经完成或序列已经匹配，题目常要求只持续一个周期。

## 上升沿

信号从 0 变成 1 的瞬间。

## 边沿检测

保存上一拍信号，通过当前值和上一拍值判断是否刚刚发生变化。

## FIFO

先进先出存储器，像排队一样，最先写入的数据最先读出。

## Testbench

专门给待测模块提供时钟、复位和各种输入，并观察结果的仿真代码。

## DUT

Device Under Test，被测试的设计模块。

## 多一拍/少一拍

状态切换、计数或输出比题目要求晚一个或早一个时钟周期，是国测中最常见的错误之一。
