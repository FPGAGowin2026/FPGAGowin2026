# 运动控制与 FPGA 定位

当前代码入口为 `FPGA_ws/boards/<板名>/src/`，状态与待验收项见 [项目交接](handoff.md)。BX72 当前使用公共机器人核心 `src/top/bx72_robot_core.sv`，两种通信不复制算法；ACG720 保留自己的融合和固件。

## 运动控制与日志分析

BX72 逻辑轮序为 FL/FR/RL/RR，对应物理 CH2/CH0/CH1/CH3，电机反向 `0xB`、编码器反向 `0xA`。现用 122880 count/输出轴圈、98 mm 轮径、160/196 mm 轴距/轮距；轮位和极性有历史悬空确认，尺度仍待物理整圈标定，见 [参数核验](../FPGA_ws/boards/BX72_138K_robot/docs/video_jetson.md)。

车体系 x 前、y 左、z 上。输入 vx/vy 单位 mm/s，wz 单位 mrad/s：

```text
r = wz * 178 / 1000
FL = vx - vy - r       FR = vx + vy + r
RL = vx + vy - r       RR = vx - vy + r
```

四轮同比例限速到 500 mm/s，20 ms 目标增量不超过 10 mm/s。50 Hz 增量速度环使用对应轮编码器反馈；FL/FR、RL/RR 两组并行、组内复用运算，两轮算完同时提交。四路编码器和 20 kHz PWM 持续并行。控制系数、制动和停止输出见 [硬件接口](../FPGA_ws/boards/BX72_138K_robot/docs/video_jetson.md)。

BX72 活动工程使用蓝牙或 UDP 控制，板载 USB 串口点动已关闭。`Scripts/motor_log_analyzer.py` 仅用于已有 ASCII 日志离线分析，不连接硬件，也不从未标定计数推导 mm/s：

```powershell
python Scripts/motor_log_analyzer.py logs/motor.log --output-prefix analysis/motor
```

默认 `--layout closed-loop` 对应 FL/FR/RL/RR；物理通道日志使用 `--layout raw-channel`。输出 CSV、SVG、summary JSON 和无效行 CSV。计数按模 2^32 求差，差值恰为 2^31 时方向不确定；主机时间只用于有合法相邻时间戳的计数率，不能当 FPGA 采样时间。

## 两板 FPGA EKF

### 模型与接口

状态为 `x,y,yaw,vx,vy,wz,gyro_z_bias`，有符号 Q16，单位为米、弧度和秒；完整 7×7 协方差使用 Q24。BX72 状态积分保留 Q32 小数余量。预测使用车体速度旋转，观测为轮式 vx/vy/wz、IMU 航向角速度及雷达 x/y/yaw；加速度和滚转/俯仰不参与此平面模型。

顺序标量更新采用 Joseph 协方差公式，共用乘法/矩阵存储资源。轮速观测使用逐轴有效掩码和动态 R，打滑/退化时不把缺测当零速度。静止约束、偏置学习条件和数值饱和均有专项回归。默认 Q/R 是验证参数，需实车数据标定。

### 时间和跨时钟

电机控制在 50 MHz，融合/IMU/N10 在约 33.333 MHz；命令、轮速和对外遥测按各自版本使用整帧邮箱或 FIFO。BX72 已删除 CPU/APB 和蓝牙融合结果的重复跨域快照。

微秒时间戳为 32 位，差值按回绕处理。陀螺使用新鲜且未消费的样本，融合 dt 来自轮速更新；超过 100 ms 的缺测先重建时间基准。传感器时间为 SPI 读取/雷达解析提交时间，不是传感器内部采样时刻。

### 雷达定位与独立避障

CSM 定位使用 64×64、64 mm 网格的局部地图，以完整扫描中点对齐有限状态历史，形成延迟创新近似；CSM 本身没有协方差回滚重放、地图滚动或回环。首次扫描用于建立子图和坐标对齐。外参与运动/年龄门限以本板 `robot_fusion.sv` 为准。

两版另增加 [DDR 雷达 SLAM 建图（历史文档已整理）](../FPGA_ws/boards/BX72_138K_robot/docs/udp_only_implementation_20261020.md)：源分支先实现蓝牙，本轮继续扩展 UDP。前端按 EKF 位姿投影实时射线，更新 1024×1024、64 mm/格的 6 bit 占据地图；管理器最多保存 32 个关键帧和每帧 64 扇区描述子，接受几何复核后的回环约束后修正 map→odom，再清图、重放关键帧并刷新 DDR tile。回环重建只重放扇区代表射线，分辨细节低于实时累积地图。该地图与 CSM 的局部子图用途不同，没有反馈为全局导航或路径点规划。

N10 点流同时进入独立避障规划器。规划器按前向扇区覆盖、距离与完整扫描有效性选择低速通道，不消费 EKF、IMU、里程计或地图；没有路径点输入。两条雷达用途均保留，不能按旧交接任务删除定位通路。

蓝牙独立使用 DDR3 保存地图；UDP 的视频双缓冲与地图通过地址隔离和用户接口仲裁共享 DDR3。蓝牙 v4 与 UDP 遥测布局未扩展为地图传输，网页雷达图和平面轨迹不能作为 DDR 建图结果验收。

### 打滑融合与接口

[打滑契约](../FPGA_ws/boards/BX72_138K_robot/docs/camera_and_localization.md)维护窗口、可观测性、动态 R、拒绝原因及独立参考。无合格雷达同窗时，一致平移打滑不可仅靠轮速新鲜度判定。

BX72 状态通过蓝牙 v4 或 UDP type 6 发布；打滑诊断不擅自扩展 UDP 120 字节布局。APB 读页和 `ekfinfo` 仅用于 ACG720，BX72 活动工程没有软核或 APB。

### 复现

从 FPGA_ws 根目录执行：

```powershell
python Scripts/run_sim.py --board BX72_138K_robot --suite fusion
python Scripts/run_sim.py --board BX72_138K_robot --suite pnr_optimization
python Scripts/run_sim.py --board ACG720_60K_robot --suite fusion
python Scripts/run_sim.py --board BX72_138K_robot --suite motor
```

合并回归覆盖独立数值参考、打滑窗口、完整融合、CSM、里程计、静止和状态发布；2760 组打滑样本与独立定点参考相差 0 LSB。构建及实板边界见 [项目状态](handoff.md)；算法相符不表示机械参数、定位误差或整板时序通过。
