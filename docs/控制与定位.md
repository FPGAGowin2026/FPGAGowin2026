### 商家参数与运动学研究

#### 源码与适用范围

商家固件 `OpenCTR_H60V32_FreeRTOS_R20_ABOT_V1.6.0/Robot/ax_robot.h` 将 `ROBOT_TYPE` 设为 `ROBOT_MEC`。`ax_kinematics.c` 的 MEC 分支包含正逆运动学；`ax_robot.c` 每 20 ms 调用一次。ROS 1 仓库 `xtark/src/xtark_robot/src/xtark_robot.cpp` 将 `/cmd_vel` 打包为串口速度指令，并对固件回传的车体速度积分为里程计。FPGA 移植直接复用本仓库已有的 `rtl/motor/mecanum_motor_control.sv`，不移植 ROS 1 通信代码或 STM32 外设调用。

### 算法映射

源固件的轮序 A/B/C/D 按运动学矩阵对应本模块的 FL/FR/RL/RR。车体坐标约定为 x 前、y 左、z 上，正 `wz` 为逆时针。原固件使用 m/s 与 rad/s；RTL 使用 mm/s 与 mrad/s。令 `L=(轴距+轮距)/2`，则四轮目标线速度为：

```text
FL = vx - vy - L*wz/1000
FR = vx + vy + L*wz/1000
RL = vx + vy - L*wz/1000
RR = vx - vy + L*wz/1000

vx = (FL+FR+RL+RR)/4
vy = (-FL+FR+RL-RR)/4
wz = 1000*(-FL+FR-RL+RR)/(4*L)
```

`rtl/motor/xtark_r20_mecanum_params.sv` 保存源固件参数：轮距 196 mm、轴距 160 mm、轮径 98 mm、每轮每圈 122880 计数、50 Hz 采样，因此 `L=178 mm`。编码器比例在 RTL 中取 `MM_PER_TICK_Q16=164`，即约 0.002502 mm/计数；与源固件浮点比例约 0.002505 mm/计数相差约 0.12%。测速模块使用累计计数之差，等价于源固件每窗读取后清零的计算方式，但负数右移有不到 1 mm/s 的取整差异。

`sim/motor/tb_xtark_r20_mecanum_port.sv` 使用这些参数验证混合速度命令、编码器测速、直行与原地旋转的正运动学。运行 `Scripts/run_sim.py --board workspace --suite motor` 会同时执行该仿真和现有电机仿真。

### 电机串口日志离线分析

`Scripts/motor_log_analyzer.py` 只读已有文本文件，不连接串口，也不发送指令。每个有效帧包含一位状态、四个八位十六进制计数和可选行尾，例如：

```text
0 00000004 00000000 00000000 FFFFFFFC
```

该合成示例按 32 位二进制补码解释，四路值为 4、0、0、-4。工具不从状态字段推断复位或机械运动；无效非空行会写入独立诊断 CSV。

### 运行

需要 Python 3.10 或更新版本，无第三方依赖。在 `FPGA_ws` 目录运行：

```powershell
py -3 .\Scripts\motor_log_analyzer.py .\logs\motor.log --output-prefix .\analysis\motor
```

默认 `--layout closed-loop`，输出 FL、FR、RL、RR 列。若日志记录的是尚未映射的四个原始输入通道，可使用 `--layout raw-channel`，列名为 CH0～CH3。工具不能从帧内容判断布局；布局只改变列名和图例，不翻转极性或应用标定。

每次运行生成四个文件：

- `.csv`：每帧原始十六进制值、有符号累计计数、相邻有效帧增量、时间间隔、计数率和诊断标记。
- `.svg`：四路有符号累计计数与相邻有效帧增量曲线。横轴是有效帧序号，不将主机收包时间冒充 FPGA 采样时间。
- `.summary.json`：有效/无效行数、布局、时间选项、限制，以及输入原始字节和分析脚本 SHA256。
- `.invalid.csv`：每条无法解析的非空行、行号和原因；空行只计入汇总。

若日志带时间前缀，工具支持 `HH:MM:SS[.fraction]`、Unix 秒、ISO 日期时间，以及方括号、`RX`、`接收`、`收`、`<-`、`←` 和 `◆` 标签。日期时间可带时区。只有前后两条有效帧都带同类型时间且间隔为正时才计算 counts/s；无时间、重复/倒退时间、混合时间格式或超出 `--max-gap-seconds` 的间隔会留空。日志时间一般是主机收包时间，只能作为观察依据。

HH:MM:SS 跨午夜默认不推断日期。确定日志连续跨过一天时才显式使用 `--clock-rollover`。无时间依据时不输出速度；工具不输出未经标定的 mm/s、rpm 或其他物理速度。

### 增量与诊断边界

相邻有效帧每路增量按模 `2^32` 取最短有符号差，适用于单次计数回绕，并假设两帧之间真实增量绝对值小于 `2^31`。恰好相差 `2^31` 时方向不可判定，该路增量和计数率留空并标记歧义。无效行不会重置前一有效帧；结果保留原始行号并标记间隔中有其他行。

状态变化不代表计数器复位，状态 `0` 也不代表轮子已经停止。已知复位前后应分开分析；只有相邻帧差而没有动作前后的静止基线时，不能推断整次行程。

默认模式保留可解析结果并返回 0。`--strict` 仍先生成输出文件，在存在无效行、不可用时间间隔或半量程歧义时返回 2，便于批处理检查。

### 回归测试

所有测试帧均为合成输入。回归覆盖 32 位正负边界、计数回绕、半量程歧义、无效行、时间前缀/时区/午夜、重复或倒退时间、间隔上限、原始/闭环列布局、CSV/SVG/JSON 输出与原始日志哈希。

## 两板 FPGA EKF

更新：2026-10-05。代码路径和复现命令以 `FPGA_ws` 为根。最新候选与实板边界见[项目状态](handoff.md#项目状态与交接)。

本实现为低速局部定位原型。融合 HDL 分别位于两板工程的 `src/fusion/EKF/`，在既有 33.333 MHz 传感器/APB 时钟域运行，不增加 PLL。四轮速度环仍在 50 MHz 独立运行；融合输出不替代各轮 PID 反馈。

代码位置：[ACG720](../FPGA_ws/boards/ACG720_60K_robot/src/fusion/EKF) 与 [BX72](../FPGA_ws/boards/BX72_138K_robot/src/fusion/EKF)。每板目录包含 5 个融合模块及 3 个 N10 扫描匹配依赖；后续共用算法修改需同步两板。2026-10-06 已移出旧根目录 N10 研究源码；板级融合工程继续引用各自本地 EKF 目录，CSM 回归位于 `sim/fusion/tb_v4_csm_submap.sv`。

### 模型与接口

状态按 `x,y,yaw,vx,vy,wz,gyro_z_bias` 排列。位置单位米，角度弧度，速度使用秒，均为有符号 Q16。车体系 x 前、y 左、z 上，航向逆时针为正。位置为本次启动的局部坐标，不是地图中的绝对位置。IMU 本版使用所选轴的航向角速度并估计陀螺零偏；加速度、滚转/俯仰及重力补偿不在此平面模型内。

预测采用车体速度到世界坐标的非线性模型：

```text
x += (cos(yaw)*vx - sin(yaw)*vy)*dt
y += (sin(yaw)*vx + cos(yaw)*vy)*dt
yaw += wz*dt
vx、vy、wz、bgz 按随机游走预测
```

完整 7×7 协方差使用 Q24，预测为 `F P Fᵀ + Q`。观测顺序为轮式 vx、vy、wz，陀螺仪 `wz+bgz`，然后雷达 x、y、yaw。顺序标量更新假定观测噪声为对角形式，采用 Joseph 公式 `A P Aᵀ + K R Kᵀ`，其中 `A=I-KH`。两遍矩阵乘法共用一个乘法数据通路，稀疏 F/I-KH 系数直接解码；P/T/N 显式同步 RAM 合并分阶段访问，综合核心矩阵占 5 块 BSRAM；恢复除法器计算增益。三角函数使用 1 度 LUT。

定点矩阵乘法取最近整数，协方差对称元素取均值，并在每次观测更新后为对角增加 8 个 Q24 LSB 的舍入裕量。双精度参考模型显式包含这项裕量。数值饱和是状态范围/噪声配置需要复查的信号，不能当作正常长期运行策略。

初始位置和航向方差为 1，速度、角速度和零偏方差约 0.1。默认噪声只用于工程验证，尚未由实车数据标定：

| 参数 | SI 方差/秒或观测方差 |
|---|---:|
| Q x、y / 秒 | 8400 / 2²⁴ |
| Q yaw / 秒 | 850 / 2²⁴ |
| Q vx、vy / 秒 | 838850 / 2²⁴ |
| Q wz / 秒 | 83900 / 2²⁴ |
| Q bgz / 秒 | 100 / 2²⁴ |
| R 轮式 vx、vy | 167772 / 2²⁴ |
| R 轮式 wz | 41943 / 2²⁴ |
| R gyro | 1678 / 2²⁴ |
| R 雷达 x、y | 167772 / 2²⁴，标准差约 0.1 m |
| R 雷达 yaw | 41943 / 2²⁴，标准差约 0.05 rad |

噪声位于 `robot_planar_ekf.sv` 的参数与 `process_noise()`。当前 IMU 读取器写 CTRL6=02，配置 ±500 dps，按 [ST 数据手册](https://www.st.com/resource/en/datasheet/lsm6dsv16x.pdf)的 17.5 mdps/LSB 转换。改变量程必须同步修改前端比例。

### 时间和跨时钟

轮速与雷达坐标单位换算共用比例乘法器，雷达安装变换的四个旋转积共用一个乘法器。两类前端运算按状态机分拍；比例单元已由独立 SI 关系检查三轴正负快照。

四轮模块以已有四轮测速快照，经新增分拍 FK 与串行角速度除法输出车体速度，附带本采样周期累计的非法 AB 跳变标志。该路径验证为 52 拍，不激活原模块里未使用的组合除法。请求/应答邮箱保持多位数据直到接收域应答，源/目的两侧仅对请求和应答做两级同步。非法编码器样本、运算核心忙或间隔异常时不接收新更新。

IMU 时间基于 SPI 数据读取完成，N10 时间基于解析后的点接收，不是传感器内部采样硬件时间；实际传感器/传输时间偏移需要标定。33 MHz 域使用相位累加器生成微秒计数，32 位时间约 71.6 分钟回绕，时间差按模 2³² 计算。EKF 的 dt 来自相邻有效轮速接收时间，标称更新率 50 Hz。短暂丢包后按实际间隔预测；超过 100 ms 的长缺测先重新建立时间基准，下一包恢复。缺测期间不宣称输出新状态。

陀螺观测要求身份/配置有效、50 ms 内采样且自上次融合后产生过新样本。每次轮速更新锁存使用的陀螺快照。同拍新样本可参与当前更新；换算期间的新样本留给下一次更新，单个陀螺样本不会在多个轮速更新中重复使用。此边界已由交错和同拍注入回归检查。IMU 缺测后轮式更新继续，零偏仅随模型预测。

### 雷达通路及验证边界

复用 N10 两层相关性扫描匹配，板级代码为 `src/fusion/EKF/n10_2d_csm_submap.sv`：64 扇区代表点、64×64 二值局部地图、64 mm 网格、4.096 m 边长。该模块新增时间和直接位姿端口；旧实验默认参数保持原有行为。

融合实例先检测完整一圈，舍弃启动/运算完成后的不完整扫描。扫描时长必须在 10～250 ms，采用扫描起止的中点作为观测时间。首次合格扫描只建立子图与 EKF 的坐标对齐，不作为独立定位观测。后续接受位姿必须通过原 CSM 的分数、重叠及置信判定，EKF 还对各位姿分量做 3 sigma 创新门限检查。

前端保存 16 个发布状态（标称 320 ms），找到距扫描中点最近、时间误差不超过 15 ms 的状态。通过该历史状态形成创新，再在最新 EKF 协方差上应用校正。**这是延迟创新近似，不是严格的历史协方差回滚和重放**；只接受年龄小于 160 ms 的观测。

首版不做逐点运动去畸变；采用保守噪声及运动范围：vx/vy 的绝对值之和不超过 0.15 m/s，wz 不超过 0.35 rad/s，同时检查即时轮速和估计速度。超速或轮速过期时清空 CSM 子图及未消费的雷达创新，恢复低速后重新建立子图，不把失真的扫描写进原子图。EKF 与电机闭环继续运行。

该地图不滚动、不执行回环或全局图优化，离开局部地图后可能无法匹配。扫描匹配与已建地图存在相关性，默认 R 是保守工程参数，不是由匹配分数推导出的统计协方差。真实退化场景、打滑、高速运动、时间偏移和长期漂移需要后续实测。主线 Jetson 若继续使用另一个 EKF，应选择原始测量或本 FPGA 融合状态，避免同源信息重复融合。

两板顶层参数可分别标定：

| 参数 | 默认值及含义 |
|---|---|
| `FUSION_IMU_YAW_AXIS` | 2，选原始 Z；0/1 可选 X/Y |
| `FUSION_IMU_YAW_SIGN` | +1，安装轴向反向时设 -1 |
| `FUSION_LIDAR_CLOCKWISE` | 0；原始角度实际为顺时针时设 1，将 Cartesian Y 反向，扫描分帧仍用原始递增角度 |
| `FUSION_LIDAR_X_Q16/Y_Q16` | 0，雷达在车体系中的安装位置（米 Q16） |
| `FUSION_LIDAR_YAW_Q16` | 0，雷达零角方向相对车体 x 的旋转（弧度 Q16） |

默认零外参是配置占位，需与实物核对；编码器轮序、每圈计数和符号仍沿用各板电机配置。

### APB 与固件

两板均扩展原只读 APB 状态页，保留 0～50 原有索引，读写解码均扩大为 `apb_paddr[9:2]`；新增索引不会写入索引 0 的 scratch。标志/年龄额外寄存一拍；整个读页在 APB 标准 setup 周期锁存、access 周期返回稳定值，PREADY 仍为常量 1，避免读页穿过 APB 反馈到 CPU 的长组合链。地址为 `0xF8000000 + 4*索引`。BX72 只提供硬件接口；本次未凭空生成其 CPU 固件。

| 索引 | 内容 |
|---|---|
| 51 | 状态标志 |
| 52、53 | 发布序号、对应微秒时间戳 |
| 54～60 | x、y、yaw、vx、vy、wz、bgz，Q16 |
| 61～63 | EKF 标量观测拒绝、输入丢弃、雷达前端拒绝计数 |
| 64～70 | 7 个协方差对角，Q24 |
| 71 | 当前子图完整扫描数，子图重建时归零 |
| 72、73 | 最近 IMU 与已对齐雷达观测的年龄（µs） |
| 74 | EKF 协方差矩阵乘法饱和计数 |
| 75 | 匹配分数高 16 位、重叠点数低 16 位 |
| 76 | 接口标识 `0x454B4631`（EKF1） |

标志 bit0=已有输出；bit1=IMU 新鲜；bit2=子图坐标已对齐；bit3=雷达新鲜；bit4=EKF 忙；bit5/6=最近一次更新使用 IMU/雷达；bit7=轮速新鲜；bit8=局部原型模式。新鲜不等于每一周期都参与更新。bit6 表示至少一个雷达位姿分量通过创新门限。

读取状态/协方差时先读 52，读取 53～60 与 64～70，再读 52；两次序号相同才接受快照。状态和协方差在一次发布中同时锁存。诊断计数为实时值，年龄/标志有一拍寄存延迟，均不属于该快照。

ACG720 固件新增 FinSH `ekfinfo`，以 mm、mrad、mm/s、mrad/s 打印状态，协方差打印 Q24 原值。需重新构建固件并配套当前 FPGA 位流；`-CheckOnly` 和宿主 C 语法检查不代表 RISC-V 链接或烧录成功。

### 上板核对顺序

1. 使用各板专属位流，ACG720 还需重新链接含 `ekfinfo` 的固件。先固定车体并读取发布序号、时间戳和新鲜标志，确认轮速在更新、矩阵饱和计数保持 0。
2. 核对四轮顺序及正负方向；前进应为 vx 正、左移为 vy 正、逆时针转动为 wz/yaw 正。BX72 的轮位、DIR 和编码器通道/极性已完成悬空轮标定，落地低速运动仍需验证；ACG720 按其板级记录单独确认。核对 IMU 安装轴及符号，静止时 bgz 可随数据逐步收敛。
3. 测量雷达安装位置、零角方向、角度递增方向；修改顶层外参后重新构建。当前外参与 Q/R 为综合参数，未增加运行时写寄存器。
4. 在有墙角等几何特征的环境缓慢移动，观察扫描数、匹配分数/重叠、雷达使用标志和拒绝计数。首次建图只对齐坐标，后续匹配才可能校正 EKF。
5. 验证传感器缺测和运动门限，再采集实车日志标定噪声、时间偏移和定位误差。先处理时序未闭合项；仿真参考误差不能替代上板验证。
