# 基于 ACG720 与 Jetson Orin Nano 的具身机器人系统总体方案

## 1. 项目定位

本项目面向选题 3“基于 FPGA 的具身智能机器人实时感知与自主控制系统设计”，目标是在 2026 年 11 月前完成可稳定现场演示的参赛作品。

项目采用 FPGA 与边缘 AI 异构协同架构：

- ACG720 负责确定性实时感知、运动闭环、局部避障、路径执行和安全保护。
- Jetson Orin Nano 负责 ROS 2、SLAM、Nav2、视觉 AI 和智能任务决策。
- 两者使用千兆以太网 UDP 通信，UART 仅用于日志和故障调试。

组委会已确认允许使用 Jetson Orin Nano。

## 2. 硬件与软件基线

## 3. 总体架构

```text
摄像头 / IMU / 编码器 / 测距传感器
                      ↓
             ACG720 / GW5AT-138
             ├─ 图像采集与显示
             ├─ 传感器采集与时间戳
             ├─ 编码器、PWM 与 PID
             ├─ 减速、停车与局部绕障
             ├─ 运动段/路径执行
             └─ 急停、限幅与看门狗
                      │
                      │ 千兆以太网 UDP
                      ↓
               Jetson Orin Nano
             ├─ ROS 2 Humble
             ├─ 传感器融合
             ├─ SLAM 与 Nav2
             ├─ TensorRT 目标检测
             └─ 搜索、跟随与任务决策
```

控制权按运行模式隔离，任一时刻只允许一个上层运动指令源。

FPGA 独立模式：

```text
物理急停
> 严重故障
> FPGA 障碍物安全限制
> FPGA 绕障控制
> FPGA 独立路径控制
> 默认停车
```

Jetson 协同模式：

```text
物理急停
> 严重故障
> FPGA 障碍物安全限制
> Jetson 运动命令
> 默认停车
```

独立模式忽略 Jetson 运动命令。协同模式禁用 FPGA 独立路径和主动绕障指令源；FPGA 只对 Jetson 命令进行限幅、减速或置零，不主动选择绕行方向。

## 4. ACG720 实时系统

### 4.1 图像与姿态显示

```text
OV5640
→ DVP 采集
→ 异步 FIFO
→ DDR3 帧缓存
├→ HDMI 实时显示
└→ UDP 图像分片（控制链路稳定后实施）
```

FPGA 负责：

- OV5640 寄存器初始化与 DVP 时序采集。
- 跨时钟域处理和 DDR3 双帧或三帧缓存。
- HDMI 图像输出。
- IMU 采集、数据有效性检查和硬件时间戳。
- 在 HDMI 画面上显示 Roll、Pitch、Yaw 及系统状态。

只实现与演示直接相关的图像格式转换或一项简单预处理，不同时开发多套滤波算法。

### 4.2 电机闭环

```text
线速度/角速度
→ 差速运动学
→ 左右轮目标速度
→ 速度 PID
→ PWM 与方向信号
→ 电机
→ AB 相编码器反馈
```

FPGA 实现：

- 编码器输入同步、滤波、正交解码和方向判断。
- 左右轮轮速测量与独立 PID。
- PWM、方向、速度与加速度限制。
- 电机死区及左右轮偏差标定。
- 用于路径执行的距离、角度和基础里程计累积。

### 4.3 实时避障

前、左、右三路测距传感器直接连接 FPGA，依距离分级处理：

```text
安全距离：正常运行
接近距离：按距离降低目标速度
危险距离：禁止继续前进并停车
障碍持续：比较左右空间并执行绕障
```

前方受阻时只禁止继续向前，保留原地旋转和后退能力，避免安全层阻断绕障状态机。

### 4.4 PicoRV32 服务层与独立路径执行

正式架构采用已经在 GW5A-25B 上完成烧录和串口实测的 Gowin_PicoRV32（RV32IMC）作为低速服务核：

- 负责 OV5640/IMU/TOF 初始化、参数管理、路径表、任务顺序、上电自检和 UART 诊断。
- 通过开放 Wishbone 写入 shadow 参数或非活动路径 bank，经纯 RTL 校验后原子 commit。
- 由独立硬件看门狗监视心跳；超时禁止新任务、请求路径中止并锁存故障。
- 不直接控制 PWM、方向、驱动使能或急停释放。

运动段执行、编码器完成判定、局部绕障和最终安全裁决仍使用纯 RTL：

```text
MOVE(distance_mm, speed_mm_s)
ROTATE(angle_mrad, speed_mrad_s)
STOP
```

指令保存在双 bank BRAM 中，并保留内部演示 ROM 作为无 CPU 后备路径。软核只更新非活动 bank；轨迹执行器根据编码器和 IMU 判断运动段完成，绕障状态机可暂停当前运动段，绕过障碍后恢复剩余路径。PID、PWM、编码器、避障和急停不迁移到软核。

### 4.5 独立安全层

- 物理急停。
- PHY 断链和控制心跳超时停车。
- 障碍物硬件减速与停车。
- PWM、轮速和加速度限幅。
- 编码器堵转和关键传感器无效检测。
- 报文长度、类型、序号和 CRC 检查。
- 故障时关闭 PWM，显示故障原因，由人工复位。

模式仲裁器的独立 RTL 基线已在 [`fpga_rtl`](https://github.com/FPGAGowin2026/fpga_rtl) 仓库实现：`active_mode_o = 0` 时只接受 FPGA 独立路径命令，`active_mode_o = 1` 时只接受 Jetson 命令；模式请求变化后立即清零运动目标，只在外部确认电机停止后切换活动模式，并保持一个时钟周期零输出再启用新指令源。复位、急停、严重故障、安全停车、切换中或当前来源命令无效时均禁止运动输出。

模式仲裁器现已接入 `robot_rtl_core` 和机器人网络纯 RTL 顶层，并与独立路径、Jetson 命令安全限制、软件/物理急停输入和电机 PI 目标联调。模式请求输入同步、真实“电机已停止”判定、板级引脚/电气连接和实板验证仍由后续真实接口完成；当前仿真和离线实现不能替代这些门槛。

不实现复杂自动故障恢复，现场安全性由“检测—停车—显示—人工复位”闭环保证。

### 4.6 当前纯 RTL 仿真基线

截至 2026-08-24，`FPGA_ws` 已实现以下不依赖实板的基线：

- OV5640 DVP RGB565 两字节组帧，禁止跨行/跨帧拼接半像素。
- IMU 六轴 12 字节原子提交，以及前/左/右三路测距偏置、量程和超时监视。
- AB 相正交解码、轮速估计、差速运动学和双轮 PI/PWM 目标。
- 前向正常/减速/停车安全层；停车、左右择向、后退、转向、绕过和航向恢复状态机。
- 外部 ROM/BRAM 握手的 `MOVE/ROTATE/STOP` 执行器，以及四段内部演示 ROM。
- `robot_rtl_core` 系统骨架，将上述模块与模式仲裁、控制报文和逻辑看门狗连接；离开 FPGA 模式会中止独立路径，物理急停或严重故障会清除缓存目标，零轮速目标会直接门控 PWM。
- `acg720_robot_network_rgmii` 将完整 RGMII/GMII 帧、IPv4/UDP Control、`robot_rtl_core`、Telemetry/Status 和最小 ARP/ICMP 连接为纯 RTL 闭环。网络域与系统域使用深度 4 的整记录异步 FIFO，复位分别同步释放，坏帧和 FIFO 满均不发布半条记录。

`FPGA_ws/Scripts/run_all_sim.sh` 统一运行 10 个 RTL 功能自检和 1 个 Gowin PLL/RGMII 板级展开检查，本轮全部通过；端到端闭环包含 72 项检查，异步帧 FIFO包含 23 项检查，精确覆盖见 [`handoff.md`](./handoff.md#51-rtl-仿真证据快照)。具体传感器协议驱动、摄像头寄存器配置、传感器/物理引脚 CDC、DDR3、HDMI、板级 PWM/编码器接口和物理急停断电未实现；系统只暴露 `path_progress_enable_o`、暂停状态和当前段类型，演示路径进度仍由 testbench 注入，不能解释为真实距离或角度闭环。

## 5. Jetson ROS 2 系统

当前 ROS 2 工作区划分为：

五个自研 ROS 包由 `ros_ws` 独立仓库统一维护，父仓库的 `Scripts/sync_ros_packages.sh` 拉取整个工作区。

```text
ros_ws/src/
├── robot/
│   ├── fpga_gateway       # 已实现：控制、遥测、状态和主机模拟器
│   ├── robot_bringup      # 已实现：launch、参数与主机闭环测试
│   ├── robot_navigation   # C++：融合、SLAM、Nav2 和激光仿真
│   ├── vision_bridge      # C++：红色单目标观测和合成相机
│   └── mission_control    # C++：导航、搜索、对准、接近和停车
└── external              # 本地 ROS 2 Humble 二进制依赖覆盖层，整体忽略、不上传
```

高级功能包的运行时节点使用 C++17/`rclcpp`，Python 只用于 ROS 2 launch。当前只实现单目标最小闭环，不增加多模型、语义地图或通用任务框架；稳定并需要独立发布时再拆分仓库。

主要功能：

- 使用 Linux 标准 UDP Socket 与 FPGA 通信，不开发内核驱动。
- 将 FPGA 编码器、IMU、测距和状态转换为 ROS 2 话题。
- 将 `/cmd_vel` 和软件急停发送给 FPGA；参数和轨迹段上传当前未实现。
- 通过 `robot_localization` 融合轮式里程计与 IMU。
- 通过 `slam_toolbox` 建图，通过 Nav2 完成点到点和路径点导航。
- 当前使用红色阈值算法完成单目标接口与任务闭环；实机阶段再替换为一个明确的 TensorRT 检测或跟踪模型。
- 实现“搜索—识别—对准—接近—停车”任务状态机。

当前已实现 ROS 2 接口：

```text
运动命令链：
Nav2 / mission_control -> /cmd_vel_nav -> velocity_smoother -> /cmd_vel -> fpga_gateway

任务与安全输入：
/mission/start          # std_srvs/srv/Trigger
/emergency_stop         # std_msgs/msg/Bool
navigate_to_pose        # mission_control 使用的 Nav2 Action

网关与融合输出：
/wheel/odom
/imu/data_raw
/joint_states
/range/front
/range/left
/range/right
/fpga/status
/odometry/filtered

感知与任务接口：
/scan
/map
/camera/image_raw
/vision/target_observation
/mission/state
```

网关只发布轮式原始里程计，不发布 TF；`robot_localization` 和 `slam_toolbox` 分别维护 `odom → base_footprint` 与 `map → odom`。Nav2 和视觉任务共享 `/cmd_vel_nav`，只有速度平滑器向网关发布最终 `/cmd_vel`。主机仿真提供 `/scan` 和 `/camera/image_raw`，实机由真实驱动替换这两个数据源。

截至 2026-08-23，主机侧 5 个 ROS 2 包已在独立 `/tmp` 构建目录和本地依赖覆盖层上联合构建成功；4 项协议 GTest、1 项 UDP launch 测试和 3 项 C++ 算法 GTest 共 8 个直接用例通过。`colcon test-result` 同时汇总 CTest 包装结果与底层 XML，因此显示 `13 tests, 0 errors, 0 failures`，不代表 13 个独立用例。运行验证覆盖约 100 Hz UDP 仿真遥测、速度命令、200 ms 命令超时归零、软件急停、断链诊断、融合里程计、`120×80 @ 0.05 m/pix` 地图、Nav2 从 `(0, 0)` 到 `(1, 0)`，以及红色目标任务状态到达 `COMPLETE`。测试只证明当前主机仿真闭环；以上均不是 FPGA 实板 UDP、FPGA 看门狗、PWM 关闭、实车或长时间运行证据。

`robot_localization`、`slam_toolbox`、Nav2 及其运行时闭包安装在本地 `ros_ws/src/external/ros_humble_overlay`，通过 `Scripts/setup_ros_dependencies.bash` 使用，不修改 `/opt/ros/humble`；`src/external/` 整体忽略，不上传。网关发布版本已为轮式里程计和 IMU 增加可配置的非零协方差初值；这些融合权重和零值传感器外参都只允许主机仿真，实机必须用测量数据重新标定和覆盖。

## 6. 千兆以太网通信

### 6.1 实现基线

以 ACG720 官方例程为底座，复用 RGMII/GMII、ARP、IPv4 和 UDP 模块，不从零自研通用网络栈。已确认的官方工程包括：

- 第 48 章：以太网硬件 UDP 协议栈。
- 第 51 章：RGMII 与 GMII 转换。
- 第 52 章：ARP 协议。
- 第 58 章：千兆以太网 UDP 回环。
- 第 59 章：OV5640 以太网 RGMII 图像传输。

当前已从第 58 章工程导入 RGMII/GMII、IPv4/UDP 收发和回环模块到 `FPGA_ws/src/ethernet/`，并在 `FPGA_ws/sim/tb_eth_udp_loopback_rgmii.sv` 建立自检 testbench。接收负载现在先写帧感知暂存区，FCS 合法才与元数据原子提交，坏 FCS、负载区满或描述符 FIFO 满会回滚整帧。现场仿真已通过“合法帧—坏 FCS—描述符 FIFO Full 信号注入—不同负载合法帧”序列，覆盖 72 字节逐字节回环、写指针回滚、拒绝帧不发送和下一帧无残留污染。

机器人网络顶层继续复用上述 RGMII、IPv4/UDP 和 CRC 模块，只增加固定本机地址所需的最小功能：ARP 帧字段与发送边界参考官方第 52 章，项目实现 ARP Request 判定与 Reply；ICMP 只实现最多 64 字节的 Echo Reply。官方第 58 章不包含完整 Ping，本项目不把 ICMP 实现标为官方例程。Control 接收检查 FCS、IPv4 header checksum、UDP 长度和可选 UDP checksum；输出 IPv4 header checksum、应用 CRC16 和 FCS，IPv4 UDP checksum 固定为协议允许的零值。

该基线的 RTL 功能仿真使用行为级 PLL 和官方 GW5A DDR 原语。2026-08-24 官方 UDP 回环、机器人逻辑顶层和 14-I/O 离线 wrapper 均完成 Gowin 综合；逻辑顶层报告 6,577 个寄存器、7,437 个逻辑单元和 29 个 BSRAM，125 MHz 网络 PLL 域综合估算为 158.532 MHz。逻辑顶层的 562 个 I/O Buffer 只用于集成可观察性，不能直接作为 PG484 板级顶层。

离线 wrapper 只引出官方 ch58 RGMII/复位管脚，将未知硬件输入固定为失效安全值，并使用 RGMII RX `/2` 作为 62.5 MHz 工具系统时钟。最终 P&R/STA 的网络 PLL 域 Fmax 为 129.443 MHz、最差 setup slack `+0.275 ns`，35,356 条路径和 20,381 个端点中 setup/hold 违规均为 0。PHY/PCB 延迟和真实系统时钟未知，未设置猜测的 I/O delay；该结果只证明内部同步路径，不证明最终板卡 RGMII 时序、PHY 或实板通信。

### 6.2 网络参数

直连或使用小型交换机，使用静态网络，不引入 DHCP：

```text
Jetson IP: 192.168.50.1/24
FPGA IP:   192.168.50.2/24
FPGA MAC:  02:00:00:00:00:02
```

| UDP 端口 | 方向 | 用途 |
|---:|---|---|
| 5000 | Jetson → FPGA | 控制与心跳；参数和轨迹段尚未定义 |
| 5001 | FPGA → Jetson | 编码器、IMU、测距和状态 |
| 5100 | FPGA → Jetson | 后续图像数据 |

### 6.3 应用层报文

使用固定二进制报文，多字节字段统一使用网络字节序：

```text
magic
version
message_type
payload_length
sequence
timestamp_us
payload
crc16
```

当前已实现的字段长度、消息载荷、CRC 参数和黄金向量以 [`udp_protocol.md`](./udp_protocol.md) 为准；修改协议时必须同步 C++ 测试与 `fpga_rtl` 中后续实现的 FPGA 协议 RTL。

当前 FPGA RTL 已实现 Control 固定 31 字节解析、CRC16-CCITT-FALSE、头部/长度/序号拒绝和序号回绕，并把固定 72 字节 Telemetry、38 字节 Status、100 Hz/10 Hz 调度接入完整以太网返回路径。`status_bits[13:0]` 和 `fault_bits[5:0]` 的冻结分配及锁存/清除语义以 [`udp_protocol.md`](./udp_protocol.md) 为准。

- 速度、角速度、距离和角度使用定点整数，不在 FPGA 协议中传输浮点数。
- 不直接发送 C/C++ 内存结构体，避免对齐和字节序差异。
- 丢弃 CRC 错误、长度错误、重复和倒序控制报文。
- UDP 丢包不重传，下一周期直接使用最新指令。
- 连续 200～300 ms 没有收到有效心跳或 PHY 断链时，FPGA 关闭 PWM。

初始频率目标：

| 数据 | 频率 |
|---|---:|
| Jetson 控制与心跳 | 100 Hz |
| FPGA 综合遥测 | 100 Hz |
| FPGA 状态 | 10 Hz |
| 图像 | 独立端口与 FIFO，根据实测调整 |

图像流与控制流必须使用独立 FIFO 和调度优先级，不允许图像拥塞阻断控制。

## 7. 运行模式与现场演示

### 7.1 FPGA 独立模式

现场物理断开 Jetson 网线，由 ACG720 独立演示基础任务 1～4：

1. 上电后检查 DDR3、摄像头、IMU、测距、编码器、急停和 PWM 零输出。
2. HDMI 显示摄像头画面、姿态角、测距、轮速、当前路径点和故障状态。
3. 按下 START 键后执行一组预设 `MOVE/ROTATE/STOP` 指令。
4. 遇到障碍物时减速、停车、比较左右空间并绕障。
5. 绕障后恢复原路径，到达终点后自动停车并显示 `FINISHED`。
6. 单独触发物理急停，证明安全功能不依赖 Jetson。

独立模式主状态机：

```text
RESET
→ SELF_TEST
→ READY
→ LOAD_SEGMENT
→ ROTATE / MOVE
→ WAYPOINT_REACHED
→ FINISHED

MOVE 期间：
→ SLOW_DOWN
→ OBSTACLE_STOP
→ SELECT_SIDE
→ BYPASS
→ RESUME_ROUTE

任意状态：
→ SAFE_STOP / FAULT
```

模式开关只能在复位或电机已停止时切换；切换时先清零运动目标，再启用新模式的唯一指令源。

### 7.2 Jetson 协同模式

Jetson 接管全局导航、绕行方向和智能任务，FPGA 仍然保留运动闭环以及限幅、减速、停车等最终安全裁决。完整演示任务为：

> 机器人从起点出发，通过 SLAM 和 Nav2 自主前往搜索区域；途中由 Nav2 选择绕行方向，FPGA 进行电机闭环、实时限速和安全停车；到达后识别红色水瓶，自动搜索并接近目标，最终停在目标附近并报告任务完成。

## 8. 赛题覆盖

| 赛题任务 | 本方案 |
|---|---|
| 任务 1：多传感器感知 | FPGA 完成 OV5640、IMU 采集与 HDMI 实时显示 |
| 任务 2：运动控制 | FPGA 完成编码器、PWM、差速运动学和速度 PID |
| 任务 3：实时避障 | FPGA 完成测距、减速、停车和局部绕障 |
| 任务 4：自主导航 | FPGA 独立路径执行，Jetson Nav2 增强全局导航 |
| 任务 5：视觉目标识别 | Jetson TensorRT 目标检测或跟踪 |
| 任务 6：智能任务执行 | Jetson 任务决策与 FPGA 安全执行 |

该分工优先保证“FPGA 实时感知与控制”和“系统稳定性”，并通过 FPGA 独立模式证明基础任务不依赖 Jetson。

## 9. 实施顺序与门槛

1. **以太网基线**：官方 UDP 回环、坏 FCS 原子拒绝、最小 ARP/ICMP、三项 Gowin 综合和离线低 I/O P&R/内部 STA 已完成；剩余真实系统时钟/复位、最终板级 I/O、PHY/PCB delay 约束、RGMII 实板时序和通信验证。
2. **控制协议**：完整 Control → 核心安全逻辑 → Telemetry/Status 返回闭环及频率调度已通过 RTL 自检；剩余电机禁用状态下的 FPGA—ROS 实板传输。
3. **电机闭环**：编码器解码、轮速估计、差速 PI/PWM 目标仿真已完成；剩余真实驱动、方向、限幅、堵转和标定。
4. **实时感知与避障**：IMU/三路测距通用前端、减速、停车与绕障仿真已完成；剩余具体器件驱动和实车标定。
5. **FPGA 独立演示**：运动段队列和演示 ROM 仿真已完成；剩余真实进度源、上电自检、DDR3/HDMI 和现场路线。
6. **ROS 2 协同**：完成 `fpga_gateway`、里程计、IMU 和 Nav2。
7. **AI 任务**：完成单目标检测以及搜索、接近和停车闭环。
8. **网络传图**：只在控制链路稳定后接入，并验证图像满负载不影响控制频率。
9. **稳定性收口**：10 月 20 日前冻结架构，之后只做标定、故障测试、长时间运行和提交材料。

当前完成度（2026-08-24）：步骤 1～2 的纯 RTL 已形成完整机器人网络闭环，覆盖坏 FCS 原子拒绝、ARP、ICMP、Control、Telemetry/Status、CDC、背压和安全故障注入，并已在固定 138K 器件上完成三项综合和离线低 I/O P&R/内部 STA；步骤 3～5 已形成编码器/轮速/PI、传感器前端、绕障和内部演示路径的系统级仿真骨架。步骤 6～7 的 ROS 主机仿真基线也已完成。尚未完成机器人真实引脚/电气顶层、PHY/PCB I/O 时序约束、RGMII/ARP/Ping 实板、本项目 FPGA—ROS 实板协议、真实传感器、TensorRT 或实车导航。当前不上实板时不再扩大算法范围，下一不可替代门槛是固化实际外设清单并完成真实板级集成。

关键验收门槛：

- 控制与遥测达到 100 Hz 设计目标，不应用倒序或过期指令。
- 拔掉网线后在设定的 200～300 ms 看门狗窗口内关闭 PWM。
- 视频流满负载时不阻断控制通道。
- FPGA 独立路线至少连续 30 次演示成功。
- 直行、旋转、停车距离和绕障参数经实车标定。
- 完整系统连续运行 1～2 小时无失控或异常复位。

## 10. 范围边界

提交主线不包含：

- FPGA 内完整 SLAM 或 Nav2。
- FPGA 内 DDS、micro-ROS、TCP 服务器或 DHCP。
- 通用 TLV、动态协议协商或多级自动通信恢复。
- 同时实现多种 FPGA 图像滤波算法。
- 多模型、多目标通用识别、大模型或复杂语义地图。
- 复杂自动故障恢复。
- 软核直接进入电机闭环或绕过纯 RTL 安全裁决。

可在主线全部稳定后增加：

- OV5640 通过 UDP 传输到 Jetson，用于 TensorRT 推理。
- 一项能清晰展示 FPGA 价值的图像预处理。
- 更灵活的坐标路径点和任务管理协议。
