# Jetson Orin Nano＋四轮麦轮＋FPGA 实时反射层总体方案

设计基线更新：2026-09-20。本文是规划，不代表功能已经实现；现有代码与历史验证边界见 [handoff](./handoff.md)。不按版本或开发阶段划分方案，不把历史频率、资源占用与精度直接作为当前指标。

## 当前工作范围（2026-09-20 补充）

电机驱动确定采用 AT8236；主要 IMU 选逐飞 IMU660RC，用户图片标明 LSM6DSV16XTR，具体接口与配置仍待资料核对，当前无对应 RTL。保留 IMU963RA，摄像头仍用 OV5640。N10 全部实现、测试及依赖原样保留，供后续 2D 雷达扩展。

当前优先功能正确与开发速度，安全基础暂不实现。下文实时反射层的风险、仲裁和故障处理属于总体设计目标，不表示当前工作区已有实现；旧差速、安全与独立路径代码已清理。本次未新增 IMU660RC 驱动或麦轮控制逻辑。当前源码范围见 [FPGA_ws 说明](../FPGA_ws/README.md)。

## 1. 定位与评分导向

面向“2026 FPGA 竞赛高云杯——选题 3：具身智能机器人实时感知与自主控制”，采用 FPGA 硬实时层＋Jetson Orin Nano 高级智能层。

> FPGA Real-Time Reflex Layer——机器人硬件实时反射层。Jetson 提供智能，FPGA 提供确定性。

| 评分方向 | 权重 | 设计重点 |
|---|---:|---|
| FPGA 实时感知与控制 | 40% | 感知—状态估计—风险判断—运动约束—执行闭环 |
| 系统稳定性 | 25% | 数据有效性、故障处理、Watchdog、输出门控 |
| 自主导航 | 20% | Jetson 定位、规划、路径点与自主绕障 |
| 创新设计 | 10% | 统一时间、轻量估计、动态安全包络及硬件仲裁 |
| AI 扩展 | 5% | D435i 与 YOLO 支持目标识别、定位和导航接近 |

功能正确、可调试和开发效率优先。FPGA 的价值是确定性时序、并行处理和不依赖上位机的安全处置，不以 Jetson 算力不足或其他处理器绝对无法实现作为理由。赛题摘录文件当前已移出工作区；基础任务在混合架构下的计分解释仍需以组委会解释为准，不据此扩展软核 SLAM。

## 4. 三个闭环与数据流

```text
Jetson：地图/定位/任务 → 规划 → vx/vy/wz 请求
                                  ↓
FPGA：指令校验 → Hardware Command Arbiter（Safety Arbiter）
                                  ↓
         Mecanum IK → 四轮目标速度 → PID ×4 → PWM ×4
                                                    ↓
                                       Motor Output Gate → 驱动器/电机
                                                    ↑
                              Fault Manager / Watchdog / 急停

四轮编码器 → QEP 与轮速估计 ───────────────→ 对应轮 PID 反馈
                        └→ Mecanum FK → 车体系速度
IMU gyro_z ─────────────────────────→ Motion Observer
                                               ↓
LiDAR/ToF → 校验、时间与有效性 → 直接近距保护 ─→ 动态安全包络 → 仲裁
                           └→ 连续性判断 → α-β → 接近速度/TTC ─┘
                           └→ 独立上传队列 → Jetson SLAM/导航
```

导航闭环由 Jetson 决定绕行方向；本地反射闭环约束当前运动；四轮伺服闭环稳定执行。FPGA 失去上位机后不要求继续自主导航，不能自动接管为旧的独立路径/主动绕障模式。

## 5. 运动控制与轻量本体估计

四轮 PID 分别使用对应编码器速度，不以融合车体速度代替轮速反馈。QEP、测速、FK、IK 必须统一轮序、滚子安装、坐标与符号约定。车体约定 x 向前、y 向左、z 向上，wz 正向为从上方看逆时针；轮径与几何参数集中标定。

轮速目标超限时优先协调缩放，避免逐轮截断改变运动方向。明确速度/加速度约束、积分抗饱和、零速与失能状态、重新使能行为。普通平滑不能延迟紧急制动；必须检查当前运动到受限目标之间的实际过渡过程。

Motion Observer 以轮式 vx/vy 为主，结合去偏后的 gyro_z 与轮式 wz 做轻量互补融合，输出车体运动状态、时间、有效性和质量信息。时间不对齐或输入不可信时降低质量、降级或拒绝融合，不输出伪精确状态。

- 加速度计不作为可靠平移速度的简单积分来源；横滚/俯仰可采用加速度计与陀螺互补估计，用于姿态显示。
- 轮式与惯性角速度残差只能提示不一致，不能唯一识别打滑，也不能发现全部平移打滑。
- 编码器与六轴 IMU 无法单独提供长期无漂移全局位置和航向；OSD 航向注明局部参考。
- 固定增益/Luenberger 观测器仅在模型、可观测性和收益明确时使用；完整 EKF、通用矩阵加速器不是 FPGA 前提。
- EKF 主要放在 Jetson；避免把 FPGA 融合状态及其同源原始测量当作独立信息重复融合。

FPGA 保持局部连续状态。Jetson 管理全局修正，并为 `odom → base_link` 与 `map → odom` 各指定唯一发布者。全局位姿跳变不重置底层闭环；由定位变化引起的新速度请求仍需安全约束。

## 6. 统一硬件时间

FPGA 使用单调硬件时间基准及启动标识。编码器、IMU、LiDAR、ToF 和估计状态携带时间与有效性，并区分：

| 时间 | 语义 |
|---|---|
| 接收时间 | 约定接收事件发生时刻，需明确首字节、帧尾或数据就绪边沿 |
| 采样时间 | 实际采样时刻或可恢复采样时刻；未知时明确标记 |
| 估计对齐时间 | 状态估计对应的共同时间 |
| 时间不确定性与年龄 | 内部延迟、传输延迟和推定误差的保守表达 |

接收时间不等于同步采样。无采样时刻时，只有具备延迟依据才可推定测量年龄；缺乏可信年龄上界的数据不能支撑严格时延保证。

Jetson 与 FPGA 建立带误差信息的时间映射，本地超时与安全链只依赖 FPGA 时钟。LiDAR Deskew 仅在点级时间或可恢复扫描时序存在时考虑，整帧接收时间不足以证明精确去畸变。

## 7. 近场风险与动态安全包络

两条并行支路：有效近距观测直接触发基础保护；连续可信距离经 α-β 估计接近速度与 TTC，用于提前干预。直接支路不等待平滑，但仍检查协议、量程和设备状态。

连续两次分区最小距离不能默认来自同一障碍。对象切换、残差跳变、间隔过长或过期时，重置或降低速度估计可信度；当前有效距离仍可用于直接保护。

以静态障碍、延迟有界和可验证制动能力为起点：

`d_safe = d0 + vT + v²/(2a)`

v 为朝向障碍的速度；T 包含测量年龄、处理和执行响应的保守预算；a 是对应方向、载荷和地面条件下实测支持的保守制动减速度；d0 包含外形、误差与停车余量。若已把测距换算成车体边界间隙 g，基础项只保留误差与余量，不能重复计入车体尺寸。

- 同时评估实际运动和请求指令，防止静止时放行朝近障碍的高速请求。
- 覆盖前进、后退、横移和旋转。车体点 r 的平面速度为 `(vx-wz*ry, vy+wz*rx)`，旋转需考虑角点及制动期间扫掠范围。
- 可采用少量边界点、方向分区或保守外接圆，不要求通用优化求解器；简化的保守性需验证。
- 若延迟期间仍会加速，应计入额外位移；年龄通过间隙收缩或延迟项补偿时避免重复计算。
- 运动障碍不能只用相对速度替换 v 就宣称停车安全，需明确障碍运动假设；TTC 提供提前干预，不代替距离保护。
- 方向覆盖未知或估计失效时，禁止将其解释为零速度、零风险或无障碍。

`TTC = 有效车体间隙 / 可信接近速度`。间隙已进入保护边界时直接保护；零接近或远离表示当前模型下无有限 TTC；无效估计表示未知，二者必须区分。2D LiDAR 扫描平面和 ToF 视场不保证全高度、全方向覆盖，适用场景与盲区需明示。

## 8. 安全仲裁与故障处理

Safety Arbiter 与 Hardware Command Arbiter 指同一最终运动仲裁职责；Fault Manager 管理故障分类与恢复；Watchdog 监测有效更新；Motor Output Gate 是最终电机输出许可。

| 输入情况 | 规划处置 |
|---|---|
| 近障碍或局部覆盖下降 | 限速、方向约束或受控制动 |
| 指令超时、ROS/Jetson/网络失联且反馈健康 | 独立受控制动，停车后保持等待；不继续自主导航 |
| 编码器异常、严重超速、电机故障 | 根据剩余控制能力采用经过验证的处置，必要时撤销许可 |
| 急停或必须硬停的严重故障 | 直接触发输出门控，不等待上传和 ROS 返回 |
| 单个非法/错误报文 | 丢弃、记录，不刷新许可；持续失效由超时处置 |

关闭 PWM/使能可能滑行，不等于受控制动；驱动器输入真值、制动能力与失能滑行需实测。软安全与硬安全分别规定动作，不能一律以“目标置零”证明安全。

需要锁存的故障必须明确故障清除、停车确认、显式重新使能及新鲜命令条件。重新收到报文不能自动解除锁存；限制解除使用适当滞回与恢复斜坡。

复位和未配置时输出许可默认关闭。同一 FPGA 内的 Watchdog 不覆盖整体失钟/掉电，若要求覆盖此类故障需独立硬件机制。状态估计、软核与上位机都不能绕过仲裁和门控。

## 9. 传感器与视觉职责

LiDAR：接收/解析 → 协议支持的完整性校验 → 时间与有效性 → 本地安全和上传两支路。上传保持扫描编号、角度、时序和缺失信息；网络阻塞不得反压本地保护。ToF 补充近场覆盖，不能据传感器数量宣称覆盖完整。

FPGA 摄像头独立采集显示，OSD 展示轮速、姿态、距离、通信、安全模式、故障、时间和有效性；灰度、阈值、边缘处理只按用途选择。

D435i 在 Jetson 上提供深度，YOLO 输出目标检测；结合有效深度、外参及观测时间定位目标，生成与目标保持距离的可达接近点，再由导航输出速度。检测框背景深度、无效深度、目标丢失均需明确处理。不开启 VLM、大模型任务规划或复杂语义地图。

## 10. 数据契约与验证边界

运动请求、本体状态、环境约束、安全结果的语义见 [UDP 与模块数据契约](./udp_protocol.md)，当前不锁定位宽和定点格式。

已固定的是平台、四轮麦轮、职责与安全链；待验证的是传感器覆盖、时间信息、保守包络、驱动制动与资源可行性。控制频率、响应时延、制动距离、观测精度、资源占用和时序裕量均需相应测量或工具证据，不引用旧差速工程数字作为新方案结论。

论证应保存观测时间、风险触发、请求/允许指令、轮速和输出许可的关联记录，覆盖横移/旋转近障碍、对象切换、过期传感器、重复乱序指令、断网、重启及恢复。主机仿真、RTL 仿真、综合/STA、板测与实车证据分别报告，不以源码存在推定完成。

## 历史电机选型记录（2026-09-09，未实测）

此前用户确认使用 MC520P30；本节保留原选型依据，不据此认定四轮整机已完成选型或验证。以下规格来自用户提供的 [产品参数截图](../190ec1f6860d7eee6499e204b67d24de.jpg)，对应其中 `MC520P30_12V` 列，尚未实测。截图路径为历史记录，本次未重新核验原件与供应商规格。

| 项目 | 标称参数 |
|---|---|
| 额定电压 / 减速比 | 12 V / 1:30 |
| 额定电流 / 堵转电流 | 0.3 A / 3 A（单电机） |
| 空载转速 / 额定转速 | 360 ± 20 rpm / 290 ± 20 rpm |
| 额定扭矩 / 堵转扭矩 | 1.5 / 4.5 kg·cm（按通常 kgf·cm 口径，约 0.147 / 0.441 N·m） |
| 额定功率 | 约 4 W（截图标称） |
| 编码器 | AB 相正交磁编码器，供电 3.3–5 V，1024 线 |

| 接口 / 输出轴 | XH2.54 6Pin / 直径 6 mm D 型偏心轴 |

`1024 × 4 × 30 = 122880` 与截图计数一致，因此可暂按电机轴 1024 线、AB 四倍频、减速输出轴每圈 122880 计数理解；这是规格推算，须手转输出轴一圈核实后再写入正式轮速/里程计参数，不能再次乘 4 或 30。按此口径，轮速 `rpm = Δcount × 60 / (122880 × Δt)`，其中 `Δt` 以秒计。轮径、轮距及四轮方向仍待标定。

用户提供的 [XTARK 官方页面](https://www.xtark.cn/product/show.php?itemid=7) 实际是 **OpenCTR H60 ROS 机器人控制器**：官方介绍支持 4 路编码器电机、6 路 PWM 电机，内置 IMU，支持串口/CAN。用户已确认此前使用 H60，后续考虑更换，替代驱动型号尚未确定。该链接不构成 MC520P30 的官方规格来源。更换选型时须核对单路持续/峰值电流、控制接口和编码器接入方式，并确认 FPGA 能执行既定电机闭环与安全停车；页面所列 12 V 5 A 是电源输出指标，不能直接视作单路电机驱动能力。

编码器供电范围不等于 AB 输出电平已确认；接入 FPGA 前需核对输出电路与目标 I/O 电压。截图功率、转速与扭矩是否采用相同额定工况也需向卖家核实，当前仅按原图记录，不作为实测功率结论。
