# BX72 跨端功能链路审查

> 历史审查：本文保留 2026-11-02 至 11-03 迁移过程中的方案和验证；文内将局部规划移至 Jetson、网页执行全局 A* 等描述已被后续设计取代。当前 FPGA 局部规划、Jetson 全局规划及现场结果见[2026-11-04 部署记录](../FPGA_ws/boards/BX72_138K_robot/docs/field_waypoint_20261104.md)。

审查对象是本 worktree 的 `FPGA_ws`、`ugv_ws` 和 `website` 三个独立仓库。以下记录当时的源码分工和迁移过程。

按当前要求，以功能链路正确实施为先，优先复用已有实现和支持逐步探索；不把额外审批或完整实车验收设为源码实现的前置条件。对失联后旧任务复活这类已复现的功能错误直接修复。

已有地面基线：在 [BX72 Flash 地面联调测试](codex://threads/01a18aee-551a-7b81-95eb-a6196140ab3b) 中，2026-10-30 用户确认三个连续航点均按顺序实际到达；记录包括先转向观察再平移，该轮没有放置障碍。后续另测绕障时用户报告中途停车和转向较慢，并选择 800 mrad/s 转向。此基线属于当时测试的位流，不能自动等同于随后部署的其他候选或新 Jetson 实现，但迁移应保留连续航点、转向观察、到达后切换等已验证行为。

## 本 worktree 的链路

| 功能 | 当前唯一在线来源及消费者 | 审查结论 |
| --- | --- | --- |
| 雷达与轮速采集 | FPGA 接收 N10、编码器和 IMU；网桥发布原始遥测、`/scan` 与里程计 | 保留已有采集及网桥，避免新增第二个设备接收者。 |
| 局部定位 | FPGA 轮速/IMU EKF 和点线 ICP 输出融合位姿；网桥发布 `/odom/filtered` 和 TF | 它为局部连续里程计，SLAM 将其用作初值；不要将两次使用同一雷达误当成独立观测再融合。 |
| 全局建图 | Jetson `global_map_node.py` 把 `/scan` 规约为前向 `/slam/scan`；slam_toolbox 输出 `/map` 和 `map→odom` | 复用现有 SLAM 与 scan 适配，不再新增全局建图链路。 |
| 局部地图和实时决策 | Jetson `jetson_local_navigation` 消费同一 `/scan` 和融合位姿，复用移植后的局部栅格与航点控制 | FPGA 源码移除原局部图和候选规划；新节点生成局部任务状态与授权速度。 |
| 全局路线和航点 | 网页服务 `global_route.mjs` 做 A*，`global_navigation.mjs` 合并地图并调度局部短段 | 与局部规划职责不同。Node 服务运行在 Jetson，浏览器留在电脑；网桥转发 Jetson 局部执行状态。 |
| 保护和控制 | FPGA RTL 的 `bx72_lite_guard` 接收原始雷达并独立限速/停车；RTL 轮速闭环、命令及 CPU 超时继续生效 | 与软件预测轨迹的车体扫掠不是重复实现，应保留独立最终保护。 |
| 视觉任务 | Jetson `car_mission` 消费同一 `/scan` 和视觉结果，速度经网桥现有授权路径发送 | 视觉目标语义与导航目标不同，继续复用控制来源仲裁，避免建立第二个直连 FPGA 的控制器。 |

网页全局路线使用 SLAM 图和新鲜局部观测；局部规划复核实时车体扫掠、未知区域和制动。因此全局 A*、局部动作选择及 RTL 近障保护虽然都检查障碍，输入、时间尺度和职责并不相同。不能仅按函数名称把它们全部删成一个检查。

迁移前，对三个仓库中已跟踪、非测试/仿真、非 vendor/IP 的 C/C++、RTL、Python 和 JavaScript 文件，按 SHA-256 检查了 300 字节及以上的完全相同文件，没有发现完全相同的生产源码副本。该检查不覆盖语义相似代码，也不代表所有重复链路均已消除。

本次实际精简了全局规划、全局地图显示和局部地图显示中各自实现的同格式 RLE 解码，改为复用同一模块；同时删除 BX72 工程清单中不被活动电路实例化的旧 RTL 三角表和仅针对该表的旧测试，以及网桥中已无生产调用的 FPGA 任务分片编解码。网桥的普通遥测与地图分片转发复用同一段代码。删除未实例化 RTL 是源码清理，不能据此声称已降低综合资源。

Jetson 的 `car_navigation` 包使用一份由旧 FPGA 栅格提炼出的共享库，在线节点和移植后的导航控制共用；FPGA 固件中原来的局部图和候选规划已移除。FPGA 融合/ICP 仍使用的 5° 归约和三角计算继续保留，因为它们服务于定位而不是第二套建图。

## 本次发现的迁移约束

1. FPGA 原始 N10 遥测以 16 点为一组打时间戳；旧固件局部地图使用 5° 代表点各自的采样时刻及历史位姿。当前 Jetson `/scan` 局部图使用整圈起始时刻和位姿近似，车辆运动时存在畸变，不等于逐束运动补偿。
2. FPGA CSM 修正时，旧固件可取得同一时刻修正前后位姿；Jetson 遥测目前只有接受计数。新节点用前一融合位姿和速度外推估算修正前位姿，计数跳变或时间条件无法匹配时重置局部图及任务。这是近似处理，实际误差和地图连续性尚待验证。
3. Jetson 局部节点是任务执行者；网桥持有控制授权并发送 FPGA 速度命令，网页根据同步状态推进队列。设备节点或网桥失联仍依赖 FPGA 命令超时停车。
4. Jetson 全局 SLAM 以 FPGA 导航遥测提供的 boot、odom 域、时钟和位姿有效性判断是否可接收扫描。`global_map_core.py` 除旧协议外接受新的 `velocity_only_v1`，新固件继续提供这些字段。
5. 雷达前向 180° 之外受到车体遮挡。未知区域、地图失效、位姿/雷达超时、命令租约和独立 RTL guard 的处理都要在迁移后的接口与测试中明确；历史文档和台架数据不能代替新架构实测。
6. FPGA 电机 RTL 和局部规划器分别维护轮速上限、速度变化和运动学几何参数；雷达外参及车体尺寸也分别出现在不同模块。bringup 已将网桥的雷达坐标系和外参传给局部节点，其余预测模型仍需与实际执行约束核对。局部规划的耗时预算尚未在目标 Jetson 的负载下实测。

局部节点的源时钟处理已过滤重放和孤立延迟包，并避免 `boot_id=0` 时反复重置。持续负向偏差由连续三个时序一致的递增样本确认后重新锚定并清图；如果这些样本实际上是持续延迟，仅凭现有时钟信息仍可能误判为漂移。

迁移前独立任务在 FPGA 本地执行；本 worktree 改为 Jetson 执行，只保留 PC 断连后继续运行的选项。Jetson 节点或网桥失联时，FPGA 按现有速度命令期限停车。视觉和导航各自使用带来源和授权代次的速度话题，避免旧发布者在新任务的授权期内插入速度。

协同任务且不允许断连时，审查发现旧网桥在网页心跳丢失后只发送 type3 零速；旧 FPGA 固件可能继续持有任务并重新提交非零自主输出。另发现网桥重启后无法从设备遥测恢复协同任务的断连策略，却可能继续为旧任务发送保活。当时的新网桥使用零速加模式停车栅栏，并在协同任务所有者或断连策略未知时停车；即使此前允许网页断连，网桥重启后也不能自动延续该协同任务。

## 参考 EGO-Planner 的 Jetson 局部规划

[EGO-Planner 论文](https://arxiv.org/abs/2008.08835)面向四旋翼局部轨迹规划，核心是用 B 样条表达轨迹，结合平滑、碰撞和动力学可行性优化；遇到障碍时利用无碰撞引导路径生成局部避障信息，而不是维护整幅 ESDF。轨迹不满足动态约束时再调整时间并复核。官方[实现与 ROS 版本说明](https://github.com/ZJU-FAST-Lab/ego-planner)可供参考。

针对本车，继续复用 Jetson 的 slam_toolbox 和现有全局 A*，未知区仍可逐步探索。`car_navigation/scripts/ego_local_prototype.py` 新增离线二维样条原型，接收已有的引导路线，在碰撞采样时生成引导项并进行时间缩放；它是对 EGO 思路的简化参考，不是完整 EGO-Planner。在线链路当前仍使用移植的既有航点和局部候选控制，离线原型没有接入电机输出。

离线原型使用圆形包络和离散采样，不具备矩形车体连续扫掠、制动尾段、实时反馈和完整时效检查，不能直接输出真实车辆速度。后续若采用在线样条，需要复用现有车体检查和速度仲裁，并按麦轮约束与新鲜观测复核；论文中的飞行器性能不能当作本车性能。

官方 EGO-Planner 仓库为 [GPL-3.0](https://github.com/ZJU-FAST-Lab/ego-planner/blob/master/LICENSE)；如果之后直接复制或修改其源码，需要按实际采用的代码和发布方式处理对应许可。本轮只参考公开算法思路，没有引入其代码。

## 迁移接口

局部导航通过 `/jetson/navigation/command` 接收任务，使用携带来源和授权代次的 `/jetson/navigation/cmd_vel` 请求速度，由唯一网桥仲裁后发送 FPGA 速度命令；网页消费节点产生的导航状态、局部地图和方向预览。FPGA 的原任务片段和局部图遥测已退出新固件运行链路，独立 RTL 保护保留。

离线导航回放原先调用已退役的固件入口，已改用当前经校验雷达输入接口。`ugv_ws/Scripts/bx72_test.sh` 也补入已有的 `car_navigation` 回归，避免只测试网桥、视觉任务和启动包。

## 本轮验证

本次迁移源码统一验证：FPGA 固件已重新生成，工程静态检查和 7 组固件主机回归通过；选定的 UDP、雷达队列、速度握手、保护反馈、遥测和 ROM 的 RTL 定向用例通过。Jetson `ugv_bridge` 和 `car_navigation` 分别构建成功，网桥最新代码 73 个 GTest 及局部导航包的 4 组 CTest 通过；后者包含实际导航节点的模拟 ROS 输入、地图、授权速度和取消检查。截止时间修改后的节点检查已单独重跑通过。`car_bringup` 单独构建通过，启动配置与网页断链停车回归通过。

跨端回归同时启动真实网桥和真实 Jetson 导航节点，以模拟 FPGA、融合位姿和雷达输入，确认网页航点请求能转成 type3 非零速度，取消后发零速与停车栅栏且旧任务不复活，没有向 FPGA 发送旧 type7 分片。时钟修复前有一次网桥已就绪但局部图未就绪，未进入航点启动断言；修复后在相同域及单播配置下复跑一次通过，不能据此断定此前偶发问题已彻底消失。实际节点命令处理和时钟处理的同进程定向检查覆盖了跨网桥乱序、过期请求、无效参数、正常取消及延迟时钟样本。这些都是模拟输入检查，不代表实际板卡时序或地面表现已通过。

网页首轮 213 项中 209 项通过，3 项因旧 FPGA 文案断言失败，更新断言后分别定向通过；另有 1 项跨仓 C++ 网关检查因未提供可执行文件而跳过。本机完整工作区构建在 `car_mission` 查找 TensorRT 的 `NvInfer.h` 时失败，故不能说整个工作区构建通过；本次改动涉及的网桥、导航和 bringup 已单独构建。以上均为软件或 RTL 检查，设备没有加载本轮改动，也没有进行本轮地面运动验证。

既有 `test_bx72_bidirectional.py` 在本机 WSL 默认 ROS localhost 环境收不到图像和 IMU；从未修改的原始基线独立构建后复现相同现象。本轮 ROS 接口和断链检查使用单播配置，仍有一次在域 196 未发现服务，换用隔离域 197 后该单项通过。旧双向全套集成未以单播配置重跑，不计为通过。

当前部署及历史实测以板级 `docs/deployment_current.json` 和 `docs/validation_current.json` 为准。工作区源码在迁移期间可能与设备上实际位流不同。

## 2026-11-03 重复校验及控制链复查

本次覆盖 BX72、Sipeed 四足、Jetson 小车、无人机、集群节点和网页的相关控制与数据链路，优先在数据入口校验一次，并复用已有结果：

- Jetson 局部任务在 ROS 入口解码后，直接以进程内类型化接口提交原有导航控制器，不再编码成旧 FPGA 分片、再重新拼包和解码。任务时序、取消和地图重置仍由持有这些状态的控制器处理。位置容差按请求的 1–500 mm 执行，不再静默缩小为 100 mm。
- 全局建图接收实际扫描角度和分辨率，部分视场保持实际范围和未知值；原先只接受 36000 点、固定起始角的限制已去除。BX72 固件去掉对 CSM 归约点新鲜度的重复运动许可及软件提交时的重复速度复核；原始雷达失联、RTL 硬件限速和近障停车仍由 FPGA 处理。近障距离保护只覆盖其现有前向和原地转向场景，并非全向避障。
- 网页停止和取消不再要求视觉观测新鲜，也能处理网页自身没有持有、但设备遥测显示存在的局部任务；取消不能下发时使用已有通用停车。乱序停车确认可继续等待另一项真实回执，后续仍依据遥测判断停止，不把请求发出视为机械停稳。
- 无人机任务复用 EGO 传感器桥已经汇总的定位、深度和外参就绪结果，并在轨迹输入时计算有效期，避免每个控制周期重复检查整条曲线。飞行中不再因为着陆状态单独超时就触发降落；AUTO.LAND 后的着陆和上锁仍等待飞控反馈。
- 集群节点共用时间戳与检测框检查，不再因为缺少类别而丢弃可定位检测；下游四足坐标转换复用上游已经确认的候选质量。观测时限和同步容差可按环境配置。四足 CAL 协议共用一次角度计算；三路串口仍各自接收，运动控制和舵机控制已复用。

跨进程/设备输入、数据是否仍然新鲜、任务状态转换与执行器最终约束并非对同一份数据的重复检查。保留这些边界并不意味着已经完成新架构实机验证。四足现有无线命令发出一次后会持续运行，串口残帧超时不等于失联停车；此行为没有在本次改动中调整。

本轮集中验证：BX72 固件已重新生成，工程静态检查和速度控制主机用例通过；Sipeed 四足 `tb_uart` 单项通过。Jetson 的 `ugv_bridge`、`car_navigation` 和 `car_bringup` 构建通过，扫描规约、局部控制、命令入口及模拟停车乱序的定向用例通过。内部任务接口改为只接收已验证数据后，旧测试直接向该内部接口输入非法值而失败；对应断言已移至真实 ROS 命令入口，重新构建和运行通过。停车用例首次因 WSL 中 ROS 服务发现超时失败，切换隔离域后通过一次，不能据此推断发现问题已经解决。

无人机和集群相关 15 个包构建通过，无人机两个包的定向用例以及集群四组测试（13 项）通过；网页相关定向测试 137 项通过。这些都是本机软件检查或定向仿真，未综合、烧写 FPGA，也未开展本轮地面或无人机实机联调。
