# ACG720 60K 六足机器人

OV5640 通过 8 位 DVP 输入 800×480 RGB565。FPGA 将完整图像写入板载 DDR3。UDP 发送端每次请求时锁定最新的完整帧，向电脑发送原生 800×480 像素。视频发送从相机配置、DDR3 校准和首帧写入完成后开始。

### 舵机接线与实测方向

俯视时，L1/R1 为前腿，L2/R2 为中腿，L3/R3 为后腿。下表按下、中、上的顺序给出球脚与增大脉宽时观察到的动作。

| 腿 | 下舵机，向上 | 中舵机，向下 | 上舵机 |
| --- | --- | --- | --- |
| L1 | A13 | A15 | A18，向左（后） |
| L2 | E16 | D17 | B15，向左（后） |
| L3 | C14 | D14 | C13，向左（后） |
| R1 | F13 | E13 | A14，向左（前） |
| R2 | B13 | D15 | C15，向左（前） |
| R3 | B16 | C17 | D16，向左（前） |

FPGA 输出 50 Hz PWM，六条腿的脉冲起点错开 3 ms。上电和 S0 硬件复位后保持输出关闭，收到运动或空格复位指令才启用。初始化姿态的下、中、上舵机基准分别为 1134、1134、1500 µs。按参考标定 12.2 µs/°，下舵机在 1134 µs 时对应向下约 30°，中舵机在相同脉宽下对应向上约 30°。左 3 下舵机（C14）的初始脉宽为 1256 µs，较 1134 µs 上翘约 10°。右 2 下舵机（B13）的初始脉宽为 1012 µs，较 1134 µs 下转约 10°。两处零位修正也用于行走。右 2 下舵机在横移时可能触及 900 µs 下限。实际角度以装配后的测量为准。

松开方向键或约 300 ms 未收到续发命令时，冻结最后输出的 18 路脉宽和步态相位。按空格以限速回到低姿态，随后保持。按板上的 S0 可关闭全部输出。

悬空调试时，如果停步后仍抖动，先看网页的实际步态是否显示停止，再点「释放舵机」作对照。FPGA 在当前帧结束后关闭 18 路 PWM，直到再次收到运动或空格复位指令。释放可能使舵机失去保持力，仅在机身有支撑时使用。

腿编号依次为 1=L1、2=R1、3=L2、4=R2、5=L3、6=R3。网页可选择以下两种连续步态。

| 模式 | 摆动顺序 | 周期 |
| --- | --- | --- |
| 标准三角 | A（1、4、5）→ B（2、3、6），相差 180° | 60 帧，1.2 s |
| 四足支撑涟漪 | A（1、4）→ B（3、6）→ C（2、5），依次相差 120° | 90 帧，1.8 s |

每组按原相位执行抬脚、摆动、落脚与推地。周期直接续接。运动中切换模式在当前周期结束后生效，静止时选择只更新下次运动的模式。两种步态均围绕初始姿态缩放原逆运动学轨迹。下、中舵机偏移为参考轨迹的 1.08 倍，上舵机偏移为参考轨迹的 4 倍，约为 1284–1716 µs。实际脚端行程由连杆几何决定。[步态控制器](src/motion/hexapod_gait.v) 在综合时读取 [步态 ROM 数据](src/motion/gait_offsets.hex)。

### IMU963RA 接线

| 模块信号 | ACG720 FPGA 球脚 |
| --- | --- |
| SCL/SPC（SPI 时钟） | F19 |
| SDA/SDI（MOSI） | F18 |
| SA0/SDO（MISO） | E19 |
| CS（低有效） | D20 |
| VCC、GND | 3.3 V、公共地 |

SPI 读到 LSM6DSR 的 `WHO_AM_I = 0x6B` 后配置三轴陀螺仪和三轴加速度计。两组 ODR 均为 208 Hz，量程分别为 ±1000 °/s、±8 g。FPGA 检查数据就绪后一次读出六轴寄存器，约每 20 ms 发布一份快照。寄存器和换算系数见 [ST LSM6DSR 数据手册](https://www.st.com/resource/en/datasheet/lsm6dsr.pdf)。

IMU 安装坐标为 X 朝前、Y 朝左、Z 朝下，静止时原始 AZ 约为 −1 g。网页通过 UDP 回传显示三轴角速度和三轴加速度。

DVP 数据、HREF 和 VSYNC 在 FPGA 输入端加 64 个 IODELAY 抽头，降低采样边沿附近的高位误读。每两个字节合成一个像素。采集端对最多短缺 8 个像素的行重复末像素，使后续行保持对齐。写 FIFO 将 8 个像素打包成一个 DDR 数据字。DDR 使用三个帧槽，采集写入会避开最新完整帧和 UDP 正在读取的帧。收齐 384000 个像素并接受最后一个 DDR 写命令后发布完整帧。相机帧结束时留出排空写 FIFO 的时间，残帧不会发布。

### D500 雷达接线

雷达 TX 接 FPGA 球脚 F20，串口信号为 3.3 V 逻辑。雷达与板卡共地，雷达按模块规格供电。FPGA 接收雷达主动发送的串口数据，在 125 MHz 网口字节时钟域识别 47 字节、12 点的数据包并校验 CRC-8。角度以雷达正前方为 0°，顺时针增加。见 [STL-19P 数据手册](https://files.waveshare.com/wiki/D500-LiDAR-Kit/LDROBOT_STL-19P_Datasheet_EN_v1.0%281%29.pdf)。

## 树莓派与集群接入

示例配置中，树莓派管理地址为 `192.0.2.54`。FPGA 通过有线口发送遥测，部署时将下表的示例 IP 和 MAC 换成板端和接收端实际使用的地址。

顶层 `camera_udp_top` 的地址参数同时供 TX 与命令 RX 使用，避免只修改视频目标后命令仍匹配旧地址。修改 FPGA 参数后需重新构建，并同步配置 Linux 应用、网卡和邻居表。

| 顶层参数 | 默认值 | Linux 对应选项或配置 |
| --- | --- | --- |
| `SOURCE_MAC` | `02:00:00:00:07:20` | 后续配置 FPGA 静态邻居 |
| `VIDEO_SOURCE_IP` | `192.0.2.10` | `--control-destination`；同时筛选遥测来源 IP |
| `VIDEO_DEST_MAC` | `02:00:00:00:00:6F` | 后续配置有线主机 MAC |
| `VIDEO_DEST_IP` | `192.0.2.111` | `--control-source`；遥测接收网卡地址 |
| `TELEMETRY_SOURCE_PORT` | `5000` | `--telemetry-source-port` |
| `TELEMETRY_DEST_PORT` | `6102` | `--port` |
| `CONTROL_PORT` | `6103` | `--control-port` |
| `CONTROL_BROADCAST_IP` | 板端 IP 的 `/24` 广播地址 | 可保留原有广播兼容；正常 Linux 控制用单播 |
| `PACKET_GAP_CYCLES` | `60000`，125 MHz 下约 480 µs | 应用发包节奏，按接收端能力调整；PHY 保持千兆 |

接收、视频转换、HTTP 接口与 ROS 2 发布统一使用工作区中的 [ACG720 接入程序](../../../ugv_ws/src/legged/legged_bridge/legged_bridge/acg720_bridge.py)。手动启动入口见 [树莓派桥接脚本](../../../ugv_ws/Scripts/acg720_run.sh)。

从工作区根目录启动接入程序时，可先仅运行 HTTP/UDP 模式；完成 ROS 2 环境配置后去掉 `--http-only` 启动 ROS 发布。

```bash
PYTHONPATH="$PWD/ugv_ws/src/legged/legged_bridge" \
python3 -m legged_bridge.acg720_bridge --http-only
```

HTTP 状态、控制和图像入口依次为 `http://192.0.2.54:8766/api/status`、`/api/control` 和 `/frame.jpg`，总控通过该服务接入。使用 SRAM 调试时，板卡重新上电后需要再次装载位流才能接收遥测。

ROS 下行入口为 `/acg720/command`（`std_msgs/String` JSON），结果为 `/acg720/command_result`，与 HTTP 共用动作、续租和停止逻辑。参数、启动及反馈语义见 [Linux 接入说明](../../../ugv_ws/src/legged/legged_bridge/README.md)。HEX1 没有逐命令 ACK，主机发送成功与异步 HXS1 观测分别呈现。

运动指令通过 UDP `6103` 接收，负载为四字节 `HEX1` 和一个命令字节。0 保持姿态；1–6 为前进、后退、左转、右转、左移、右移；7 释放舵机；8 回低姿态；9 选择标准三角；10 选择四足支撑涟漪。

板端通过 UDP `6102` 回传 `HXS1`：第一个状态字节低 3 位为请求方向，位 7 为所选模式，位 6 为实际轨迹模式；第二个状态字节低 3 位为实际方向，位 7 为复位中；第三个状态字节低 7 位为帧索引，位 7 为 PWM 已启用。模式位 0/1 分别表示三角/涟漪。后三字节按高位到低位包含 RX 时钟心跳、接收起始、SFD、长度与 FCS 通过计数，均为 6 位 Gray 编码。

每个视频包的 UDP 负载为 1288 字节，依次包含 4 字节标识 `ACV2`、大端 16 位帧号、大端 16 位块号和 1280 字节小端 RGB565 像素。块号从 0 到 599，每块对应光栅顺序中连续的 640 个像素，可跨行。发送端以 50 MHz 从 DDR FIFO 预取完整包，通过两个双时钟缓冲交给 125 MHz 发包域。树莓派现场接收能力低于满速重复发帧，当前包间隔参数为 60000 个字节时钟，约 480 µs，以避免应用缓冲溢出。读取快于相机采集时，会再次发送最新完整帧。接收器也支持此前的 `ACV1` 格式，每帧 960 块，每块 400 像素。当前位流只协商千兆全双工，对端需支持千兆自动协商。

同一 UDP 端口还接收 22 字节的 IMU 遥测包，按 `struct.unpack("!4sIBB6h", data)` 解码。字段依次为 `IMU1`、32 位发包序号、状态（bit 0 为样本有效）、器件 ID、`gx gy gz ax ay az` 六个大端有符号 16 位值。换算比例为每 LSB 0.035 °/s 和 0.000244 g。IMU 包在视频包之间发送。

雷达包共 51 字节，依次为 `LDR1` 和 47 字节原始串口包。串口包以 `54 2C` 开头，速度、起止角度、12 个距离和强度测点以及时间戳使用串口原始字节序。末字节为 CRC-8，初始值为 0，多项式为 `0x4D`。雷达包与视频和 IMU 共用 UDP 6102。

## 构建与烧录

用 Gowin IDE 打开 [ACG720 工程](ACG720_60K_robot.gprj)。器件为 GW5AT-60B（GW5AT-LV60PG484AC1/I0），顶层为 [camera_udp_top](src/top/camera_udp_top.v)。依次运行综合和布局布线，编译完成后在 `impl/pnr/` 查看时序报告和生成的 `.fs` 位流。需要上板调试时，在 Gowin Programmer 中选择对应器件和该位流，执行 SRAM 编程与校验。

相机像素时钟 PCLK 接在普通 GPIO B1，布局布线会提示使用通用布线。DVP 外部延时和 PCB 偏斜采用工程预算，实际板卡需对照[时序约束](src/constraint/camera_udp.sdc)核对。

## RTL 实现约定

| 部分 | 约定 |
| --- | --- |
| UDP 发送 | 一份固定包头、一个字节计数器，启动时锁存元数据；忙时启动请求忽略；不足 18 字节的 UDP 负载补齐以太网最小帧 |
| I²C | 字节层共用四相位控制；寄存器层共用读写调度；保留读寄存器时先 STOP 再 START 的 SCCB 流程 |
| 相机采集 | 两字节合成 RGB565，保留十帧预热；移除未使用的图像状态和坐标输出 |
| 遥测跨域 | IMU、运动状态和 RX 调试计数在同一时刻组成 153 位快照，约 20 ms 发布一次 |
| 步态 | 1080×162 位 ROM，标定与限位由步态控制器处理 |
