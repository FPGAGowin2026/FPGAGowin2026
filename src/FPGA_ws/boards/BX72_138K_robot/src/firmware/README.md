# FPGA 局部导航基础模块

用 Gowin IDE 打开 [BX72 板级工程](../../BX72_138K_robot.gprj)。器件为 GW5AT-138C（GW5AT-LV138PG484AC1/I0），顶层为 [robot_top](../top/robot_top.sv)。工程直接综合已有的 [ROM 包](../softcore/bx72_nav_boot_pkg.sv)。GoRV32 FP 核的安装来源和版本校验见[厂商核说明](../softcore/vendor/gorv32_fp/README.md)。

修改固件 C 源码后，在含有 `BX72_138K_robot.gprj` 的板级目录运行以下命令，更新 ROM 包，再在 Gowin IDE 中重新综合并运行布局布线。

```sh
python3 tools/build_firmware.py
```

[固件构建脚本](../../tools/build_firmware.py)使用 `riscv64-unknown-elf` 工具链，并将固件和清单写入 `impl/firmware/`。在 Ubuntu 22.04 上用 GCC 10.2.0 重建时，生成的 ROM 包与工程中的文件逐字节一致。

这些模块由 `main.c` 与板级软核平台连接，已接入雷达、IMU、编码器、以太网和电机控制链路。当前 `robot_config.h` 沿用地测试验值：x/y 制动减速度 200 mm/s²、yaw 制动减速度 1500 mrad/s²、响应和观测时间误差各 100 ms。这些值为试验参数，实车部署时需要标定。

- `odometry.c`：平面 EKF，融合四轮速度和按配置方向使用的 IMU z 轴角速度，提供短时位姿历史。四轮顺序为 FL/FR/RL/RR，x 向前、y 向左、yaw 逆时针为正；安装轴和符号以 robot_config.h 与 bridge 的现行配置为准，更换安装需重新确认。噪声及初始方差由配置提供；横向打滑、轮速误差和零偏需要实车标定。处理过程假定三项轮速观测误差独立，实际相关性和精度尚未验证。六轴 IMU 无法单靠陀螺仪提供全局绝对航向。
- `local_map.c`：64 × 64 格、50 mm 分辨率的滚动局部图；使用空闲/占据/未知和观测时间桶。有效期需要配置，过期后为未知。调用方只提交有意义的有效雷达射线，并按采样时间顺序输入。
- `local_plan.c`：基于地图快照的增量 A*，规划固定朝向的连续平移参考，未知或不够新鲜的区域不可通行。导航调度每次展开一个节点，并按车体朝向缩小待检查的栅格范围；输出是建议路径，不能代替实时运动许可。转向需要单独考虑车体扫掠。
- `route_follow.c`：沿规划点连续产生平移参考速度，不要求在中间点停车；在最终目标附近请求减速，并在每次输出时调用运动范围检查。转向与重新观察由导航层调度，其实车行为仍需验证。
- `local_guard.c`：按车体、四轮速度上限、地图新鲜度和给定制动参数检查自主运动与制动范围。0.3 m/s 是稳定横移目标的下限，停止和加减速过程不受此限制。雷达近障硬件保护需持续运行，本模块不能代替它。
- `footprint.c`、`runtime.c`：分别提供地图栅格与车体相交计算、裸机编译所需的字节复制函数。

`local_map_t`、`local_plan_t` 和 `odometry_t` 应静态分配，避免占用软核小栈。每次构建的 ROM、静态 RAM 和预留栈大小见生成的 `impl/firmware/manifest.json`。控制间隔实测仍有超过 20 ms 的情况，尚无最坏耗时保证。

`local_guard_config_t` 的制动减速度、响应时间和观测时间误差目前使用上述试验假设，尚无实车标定值。后续标定应反映组合运动下保守的实际制动能力；主机测试中的数值也不能当作车辆标定数据。
