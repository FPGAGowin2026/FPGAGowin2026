# BX72 机器人网页工作台

当前集群成员为 BX72 小车与 ACG720。ACG720 卡片通过树莓派的桥接服务（8766 端口） 显示 FPGA、IMU、D500、相机及 PWM 状态，并单独显示 `/acg720/status` 的 ROS 2 跨机心跳。`/api/fleet` 返回 `swarm_ws/config/robots.json` 中的名册；`/acg720/api/status`、`/acg720/frame.jpg`、`/acg720/api/control` 转发到 ACG720 服务，部署时将环境变量 `ACG720_UPSTREAM` 设为实际桥接 URL。启动脚本继承该变量，systemd 用户服务可通过 `Environment=` 设置。单独运行网页服务时，`--acg720-upstream` 可覆盖该值。默认地址 `198.51.100.39` 为示例地址。Jetson 默认手动入口会同时启动 ACG720 的雷达里程计与本地建图，并指定初步实测的相机内参和安装外参。跨机地图对齐仍需两台相机共同观测 AprilTag 并在现场验证。

小车与 ACG720 各有手控入口、状态和视频。键盘仅作用于当前明确选择的机器人，切换目标会结束上一目标的手控。

| 手控目标 | 网页控制与状态入口 | 设备反馈 |
| --- | --- | --- |
| BX72 小车 | `/manual`、`/stop`、`/api/state` | 控制会话、四轮目标/反馈/PWM 和任务状态 |
| ACG720 六足 · `/acg720` | `/acg720/api/control`、`/acg720/api/status` | HEX1 下发、HXS1 请求方向/实际步态/PWM 状态 |

ACG720 的 `delivery="sent"` 表示树莓派已调用 UDP 发送，`acknowledged=false`：HEX1 没有逐命令 ACK，实际模式和步态另看新鲜 HXS1。`stand`/`home` 回低姿态，`release` 关闭 PWM，`tripod`/`ripple` 选择步态模式；模式选择不启动行走。

本目录统一维护现役网页、静态资源、代理服务和网页测试。`swarm_ws` 仅提供协同 API，`ugv_ws` 提供机器人节点；本目录不依赖旧规划器目录。网页使用 Jetson 的现役架构：网页服务订阅 ROS 2 传感器和 FPGA 状态，并转发 8081 视频、地图、航点、探索、手动控制和停车接口。服务入口是 `dashboard_server.py`。

页面脚本入口为 `map_palette.js`、`hexapod_manual.js`、`robot_app.js`、`swarm_app.js`、`acg720_app.js`；界面和代理检查源码位于 `test`。

小车和网页通过现有脚本在同一个终端手动启动。在 Jetson 的项目根目录执行：

```bash
cd ugv_ws
bash Scripts/bx72_run.sh
```

脚本默认启动小车任务、视觉、六足建图和协同台，并启动或复用 8765 端口的网页。只运行小车航点时可用 `bash Scripts/bx72_run.sh car enable_vision:=false`。按 `Ctrl+C` 结束本次 ROS 启动及随脚本启动的网页进程。由 `bx72-dashboard.service` 管理的网页独立运行。用户服务默认在 `~/FPGAGOWIN/src/website` 启动，其他安装位置可通过 systemd 用户服务覆盖项设置 `WorkingDirectory`。小车正在执行任务时，先在网页请求停车并确认四轮停止，再退出脚本。

开发时若需单独调试网页，在已启动小车节点且未运行其他网页实例的情况下，从项目根目录执行：

```bash
cd website
source /opt/ros/humble/setup.bash
source ../ugv_ws/install/setup.bash
python3 dashboard_server.py --bind 0.0.0.0 --port 8765
```

电脑连接同一网络后，通过 Jetson 当前 IP 的 8765 端口访问网页。单独调试网页时，也可在完成 ROS 环境加载后运行 `npm start`。网页服务需要 Python 的 OpenCV、NumPy 和 ROS 2 的 `tf2_ros`。避免重复启动网关或视频实例占用 FPGA 视频和遥测端口。

手动控制需要先在网页允许控制，然后按住方向键；松开、页面失焦或隐藏会请求停车。网页停车是软件请求，以四轮反馈和现场状态为准。地图可连续选择最多 32 个航点，再次点击已选的待提交航点可取消，也可调整顺序和删除；橙色虚线仅表示待提交航点顺序，紫线为导航端返回的路线。导航节点支持多航点状态时，网页一次提交完整队列，并显示当前航点、完成数或失败原因；HTTP 接收不代表导航已接管。已提交任务的取消仍使用任务按钮。旧导航节点仍可提交单个航点，多航点提交会等待接口就绪；还可请求探索。

“协同建图 · 手动移动”按协同服务配置的 `participants` 展示小车与 ACG720。成员卡分别显示接入在线状态、地图与接收时间、相机内参、安装变换、AprilTag 对齐和自动导航能力。标定缺失只影响该来源的视觉对齐，不影响它的 D500 局部图或独立手控。ACG720 作为唯一成员或坐标基准时，成员卡同样按实际加载情况显示标定状态。位置按后端 `pose_reference` 显示。六足的位置参考点是 `acg720_lidar`。加载机头偏角后，地图箭头和角度按机头方向显示。

“实时局部地图”可切换小车或六足，并下载当前来源的栅格。小车显示 FPGA 发布的局部图（`/local_map.png`）。六足使用当前 D500 扫描（`/acg720/scan`），在雷达坐标下生成 64×64、5 cm/格的栅格（`/acg720/local_map.png`）；只有有效测距经过的格子标为空闲，窗内回波端点标为障碍，其余格子保持未知。任一来源过期时隐藏实时预览。

“SLAM 建图”展示两台机器各自坐标系中的累计地图。`/swarm/api/map?view=car|acg720|common` 由网页代理原样转发。共同图只合并后端报告已对齐且有地图的成员，并显示实际来源、坐标基准和坐标系；已对齐成员离线时仍可查看标明接收时间的历史地图。地图服务发布后网页自动接入。

参与成员相机观察共同 AprilTag 后由协同服务计算初次对齐，结果需要现场验证。随后可通过“进入手动遥控”选择小车或 ACG720 移动并继续建图。自动探索放在独立折叠区，缺少自动导航能力时不妨碍地图查看和手控；打开页面、状态变化和查看地图都不会提交运动目标。协同探索未运行时，可主动点击“重新识别 AprilTag”清除旧对齐并等待再次观察标签；请求被接收不代表对齐完成，以后端状态为准。

地图在网页上以浅蓝显示未知区域、白色显示空闲区域、深色显示障碍，灰度源图中间值按占据程度渐变。配色只用于显示，导航栅格数据和下载的原始地图文件不变。地图接收时间超过 30 秒会标明“保留上次地图”；已对齐成员离线后保留的图属于历史地图，不表示机器人仍在线。后端清除对齐时立即隐藏旧共同图；协同接口中断时隐藏相关地图，避免把旧位姿当成实时数据。

网页主图和全局规划共用导航节点发布的 `/robot/navigation_map`。选点时，末航点的方框按地图比例画出含边距的 30 × 29 cm 车身，框内短线指向车头。待提交时预览当前车头方向，提交后显示任务记录的终点朝向。

新鲜的 FPGA 局部图完整覆盖全局格并确认空闲时，该格立即显示为空闲。局部占据和当前雷达命中优先。局部覆盖退出后，连续三帧激光确认清除的旧障碍可继续显示为空闲，最后一次有效空闲观测满 4 秒后转为未知。在同一次建图中，收到第一张导航图前可查看 SLAM 底图。此后若融合图暂不可用或新图加载失败，主图保留上次导航图并标记过期。`/map.png?raw=1` 可单独查看原始 SLAM 底图。

主图、小车自身 SLAM 图和包含小车的共同地图均显示小车轨迹；主图紫线表示导航路线。网页只记录打开期间的有效位姿，移动至少 3 厘米才增加采样；刷新后重新记录。定位或网络中断、定位恢复计数变化时，实线分段，前后有效位置用虚线连接，并提示“轨迹记录有缺口”。虚线不代表实测路径，不补中间位置，也不据此断言发生搬运。小车地图坐标系改变时清除旧坐标系轨迹。协同地图共用一份小车局部坐标轨迹，并用当前同一状态中的局部/共同位姿变换到共同坐标系；只有 ACG720 的单源图不混画小车轨迹。地图栅格外的有效位置通过显示留白呈现，不修改原始栅格或下载数据。定位失效时保留历史分段，隐藏当前小车圆点，并明确显示正在重定位；确认阶段显示已确认帧数，恢复有效定位后再显示当前坐标。地图仍在更新不代表当前位置有效，先前的失锁原因也不代表当前扫描平面仍然异常。

小车停车结果不明时，仅现场确认停止后才能提交停车确认。ACG720 手控按住动作续租，切换目标、失焦或松开会结束原动作；停止仅冻结当前姿态，关闭 PWM 使用独立的释放舵机操作。协同接口由网页服务转发至 Jetson 本机 `127.0.0.1:8767`。

视觉框来自 TensorRT 检测与 ByteTrack，叠加显示与视频不是逐帧同步。跟随和接近从检测框或列表选择目标；搜索并接近按类别及可选红色筛选，在原地转动搜索，不启动地图探索。目标丢失后，跟随和接近停车等待原 ID；搜索在检测画面仍有效时恢复原地转动。人员类别表示检测到人，不是身份识别。

视觉按检测框中心的水平偏差直接转向。跟随不前进；接近在目标居中后前进，FPGA 前向近障保护触发时结束。视觉不需要关联目标的雷达回波或等待地图定位，底盘原有雷达保护仍生效，任何前向近障都可能触发停车，不代表障碍就是视觉目标。实际相机左右方向需现场确认，必要时调整 `vision_mission.left_image_turn_sign`。

启动时图像或地图未就绪可稍后自动恢复；网页逐帧确认 JPEG 解码，并在图像中断后重试。页面提示信息代表链路和任务状态，不代表导航、避障、制动或地面行驶已经验证。雷达只能看到前方，实际行驶需现场检查盲区。`npm test` 的现有入口覆盖页面控制、航点、视觉、双机器人接口与可选建图成员逻辑，包括未标定 ACG720、单机图、成员离线和手动建图与自动探索分离。

在已加载 ROS 2 和 `ugv_ws/install/setup.bash` 的开发环境运行 `python3 test/swarm_proxy_integration.py`，检查协同 API 与 ACG720 的代理隔离、并发请求、JPEG、HTTP 错误、旧入口删除和单台掉线；测试只使用独立本机上游，不连接机器人。部署前端静态资源后刷新页面即可加载；只有修改 `dashboard_server.py` 或上游启动参数才需要重启网页进程，不要因此启用开机服务。
